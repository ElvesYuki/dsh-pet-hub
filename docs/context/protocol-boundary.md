# 设备协议边界（设计，尚未上机）

详细设计以[hub-device/1草案](../protocol/hub-device-v1.md)为准；[迁移/回退](plans/legacy-v4-migration.md)及[模拟验收](plans/device-simulator-acceptance.md)均未执行。以下为早期边界摘要，不表示当前代码已实现。

## 分层与兼容

PET4是素材文件编码，bridge v4是已有单设备HTTP协议，hub/1是拟议管理协议：三者不能混用版本号。旧固件没有身份/心跳，不能根据IP编造device_id或通过现有played接口伪装多设备支持。迁移期显式legacy单设备模式，新协议固件单独协商，禁止静默升级。

## 身份、能力与角色

设备生成持久随机device_id与设备密钥（非MAC/IP身份）；每次启动新的boot_id，管理端有controller_id，绑定有binding_id与credential_epoch。发现记录不可信，完成设备侧限时配对确认与密钥证明才绑定身份，重置设备身份视为新设备。

能力报告需schema_version、协议范围、固件版本、屏幕宽高/形状/色彩、编码、asset_max_bytes、缓存槽数/大小、输入/输出能力。当前期望profile是240×240圆屏、PET4、4×3MiB；不能在代码中默认未来设备有这些能力。未知必需版本/编码拒绝，未知可选能力忽略；角色包独立character_id/version/规格/语义映射/素材SHA-256/许可清单，不重新编号46动作。

## 播放与心跳

每设备目标包含device_id、binding epoch、boot_id、controller fence、command_id、revision、character/package hash、action_id；同命令重复应答幂等。设备独立回执accepted/downloading/verified/playing/failed/cancelled；只有playing确认启动展示计时，绑定/启动/控制代数和目标修订不匹配的确认不得推进其他设备。P0只实现boot/revision/action的内存校验，其余为后续协议要求。

拟议心跳间隔5秒、15秒进入stale（待实测调优），携带boot_id、单调seq、播放目标及下载/缓存诊断；不要泄露SSID/密码。离线继续已有缓存，源掉线与设备掉线分别呈现；不能声称支持冷启动离线播放。

## 绑定、解绑、恢复

BLE仅用于限时配网/身份确认，素材走Wi-Fi。配对验证码只作设备确认，不能直接当长期密钥；需经过审查的密钥交换与加密认证通道（具体方案P2选定），防重放/限次数/取消销毁临时秘密；热点和LAN绑定也必须经过设备确认。凭证存系统安全存储，UI只拿引用。LAN发现只给候选，不能信任广播身份或直接发命令。

解绑在线需设备撤销旧epoch及管理端删除秘密并确认；离线只能标记“本机移除、设备撤销待完成”，不能展示完全解绑。设备恢复出厂走设备侧确认。自动重连按device_id+密钥证明恢复，不能依赖旧IP；指数退避加抖动（建议1–30秒），单设备一条下载队列，旧连接/旧epoch回执全部丢弃。先核验能力和包摘要再续传/下发，不每次重连重写Wi-Fi。

## 进程、端口与配置仲裁（P1必须实现）

一个用户一个hub服务；插件/独立应用均为客户端，不各自拥有设备桥接。以OS互斥/用户目录独占锁选主，持有锁才创建IPC与LAN监听；竞争者只连接现有实例。优先Unix socket/平台命名管道，端口动态申请并将端点写入0600服务描述；不要复用或探测后强占18764。进程PID不是锁证明，过期锁必须验证所有者和实例随机nonce；禁止仅因超时杀进程。

IPC按本机用户鉴权，暴露设备管理白名单命令，不能代理任意DSH接口/任意URL；配置仅服务写入，schema版本+revision CAS+原子替换，秘密留安全存储。设备端需持久控制代数fencing/租约，防止旧服务复活后继续下发；服务是唯一调度器，客户端UI断开不重置设备。插件卸载释放自己的订阅/路由/定时器，不能杀死仍被独立应用使用的共享服务。P1已实现同一canonical runtime目录内的Unix socket单实例及配置CAS；插件与独立应用须使用同一路径。服务异常退出遗留socket不会自动抢占，先离线核实再恢复。设备fencing、凭证库和LAN传输仍未实现；当前服务不能下发动作。
