# 轻量分层角色、表情与对话口型规划

2026-10-30。状态：桌面视觉原型部分实现；[四态候选](../../reports/2026-10-30-character-states.md)与[无音频五嘴型/说话组合](../../reports/2026-10-29-character-speech-preview.md)已交付。四态桌面候选已实现：待机/思考/工作三基础态与单次完成反馈，切换保留弹簧连续性，触摸结束回到最新基础态。360基准/原点、全部11发束及既有贴图保持；10段2890次覆盖/安全区采样候选为0，194项测试通过。视觉辨识度和自然度仍待用户确认；真实音频同步继续延后真机阶段，原46动作保持。

## 1. 基线与目标

- 当前目标为1.75C／ESP32-S3，板级记录466×466屏幕、8MiB PSRAM、32MiB Flash；精确部署与实际资源以[正式基线](../native360-baseline.md)及后续测量为准。
- 已有PET4宿主解码与角色包验证，不等于新分层渲染、音频或口型能力。原生360正式版实际FPS尚无本规划独立测量，不沿用旧板24FPS或RAM评估版16.3FPS。
- 新路线主要承担待机、表情、触摸即时反馈和说话；复杂舞蹈、转身、魔术和大幅形变继续由PET4承担。
- 保持现有360素材对应的人物大小、位置和原画布中心；466是物理显示范围，不自动放大人物。取消300/320等缩小扩容候选，不逐动作重新居中或动态取景。

## 2. 形象与素材制作

先建立角色参考表：以当前待机及动作画面确定人物比例、构图与画风，以原作者及授权二创设定核对脸型、发型、服装、配色、头饰和尾巴。不同二创版本不随意混搭；该形象不称DeepSeek官方角色。静态合成与动作观感须经用户确认，不能以技术简化替代形象一致性。

按用户最新要求完整纳入头发细分与动态，暂不以性能限制视觉设计：头顶主体1、刘海3、侧发2、后发3、呆毛1、左右长发末梢2，共12层。头顶主体随头固定，其余11层全部预留独立动态，头饰/耳鳍随头，尾巴独立。原“首版只动5处、刘海/末梢延后”方案被取代。先完成视觉效果，再测量优化，不预先合并头发、缩小人物或删减动态层。详见[头发细分规范](../../art/character-production-guide.md)。保留源图，补全遮挡和关节重叠；侧脸、举手使用额外姿态图。

制作坐标对齐当前360居中基准，并明确映射到466屏幕的偏移、安全区和支点；具体坐标约定在素材Spec冻结。发布图裁掉透明空白、记录原位置，不通过裁切丢弃角色或道具。全动作检查头发、尾巴、手部、道具及特效边界。

首版设计包含父子关系、固定支点、平移、小幅旋转、少量缩放、贴图替换和固定绘制顺序；头发需呈现刘海错相、侧发根定梢动、后发延迟、末梢回摆、呆毛回弹，以及呼吸/转头/停止/触摸的层次反馈。可用关键帧、程序曲线或简化阻尼跟随，不以完整网格/物理SDK为前置要求。基准大小与位置保持；其中呼吸/头发次级运动/停止/触摸已有桌面候选；贴图替换与设备适配仍待实现。

## 3. 动画组合与本地交互

分离基础动作（呼吸、思考、工作）、表情（眼眉、脸红、汗滴）与嘴型通道。定义参数所有权、组合表、优先级、过渡和中断，避免笑眼眨眼冲突或不协调的情绪嘴型。基础通道可以循环，短反馈结束后回到当前基础状态，不恢复已过期意图。

头发作为基础姿态之上的独立次级运动层：根部随头部，发束和末梢错相/延迟跟随；触摸短反馈与其有界组合，不能覆盖眼眉嘴或改变角色原点。静态重合后逐层启用全部11处动态做视觉检查，重点看根部露缝、末梢折痕、穿插、过度摆动和头饰漂移。具体幅度、衰减与跟随参数由完整效果预览确定，当前不因预估性能限制开放数量。

触摸在设备本地命中角色区域，支持摸头笑脸轻晃、身体点击短弹动、有限眼神跟随。连续触摸限频限强度，部件预载，不等待电脑往返或现场下载。任务语义继续来自pet，经hub适配；不重复监听DSH会话，不调用pet配置、播放或状态写接口。

## 4. 对话与口型

**安排调整（2026-10-29，用户决定）**：真实音频播放、音量驱动开合及时间戳口型同步延后到真机阶段，移出当前桌面实施顺序；不继续制作桌面真实音频同步原型。现有五嘴型、无音频开合、暂停/换句/取消和表情组合保留。该调整是实施顺序选择，不把无音频预览当成真实说话或声画同步已验收。

恢复条件：用户明确恢复该项后，先核对目标机器的音频输出链路、实际播放进度获取方式和分层渲染基础，再写专项Spec/Diff。真机验收覆盖播放/刷新时钟、静音闭口、暂停/打断/换句、欠载/断网恢复、声画偏差与音频/动画并发资源；音量开合与更精确的时间戳口型分阶段验收。设备连接、固件修改或烧录仍须相应授权，本次记录不启动真机操作。

以下为延后保留的技术目标：

1. 先准备约5–6种嘴型：闭嘴、微张、大张、圆嘴、微笑等；实现开始、停顿、结束、中断。只有文字时属于模拟说话，不称发音同步。
2. 音频播放链路独立设计后，先以实际播放音量驱动嘴部开合，不宣称精确口型。
3. 后续由宿主或语音服务生成带时间戳的口型序列，设备跟随实际音频播放进度，而非消息到达时间。音频、口型、情绪绑定播放会话与代数；暂停、打断、换句共同取消旧数据。

首版不在任意PET4帧上覆盖嘴部：视频头脸会移动且含原嘴型。对话先切到分层角色；音频流缓冲、欠载、断网与同步恢复须专项设计。已有硬件记录不等于音频播放实现或验收。

## 5. 渲染、内存与双路线协调

首个设备原型候选：部件贴图→参数求值→LVGL软件合成→变化区域刷新→现有屏幕驱动。核对实际LVGL版本、透明与变换支持；如有瓶颈，依据测量优化热点，不预先重写全部显示层。

- 预转换设备贴图格式，优先评估RGB565加Alpha；常用图预载，避免交互时PNG解码。最终格式、透明精度和容量待原型定案。
- 刷新覆盖部件新旧区域，恢复背景并重绘区域内所有重叠层；跳帧时保留累计变化。不得只清旧图而遗漏其他部件，也不通过全帧像素比较作为默认变化检测。
- 同一显示流程拥有缓冲，异步刷新完成前不得复用；宿主预览、动画纯逻辑、runtime资源管理与固件渲染适配分离，核心不依赖DSH/DOM。
- 按解压贴图、合成/刷新缓冲、PET4活跃资源、音频、网络与瞬态分配核算峰值。不能把两套播放器直接叠加到现有内存预算，也不以PNG文件大小代替RAM占用。
- 当前以完整视觉制作优先，性能优化后置；测量时单独记录12层头发及11处动态的合成/透明重叠成本，优先缓存、变换计算和变化区域优化。没有实测前不以减少发束或整体摇动替代目标效果，实际设备帧率仍未知。
- 共用上层动作语义和确认，由分层或PET4播放器之一拥有主体。切换匹配角色、基准姿态、颜色、位置与大小；明确资源预留、释放、失败保留旧画面和取消策略。不能承诺内存不足时仍同时预载两套完整素材。

现成同形象Live2D运行模型仅作为调查与参考；尚未确认可编辑源工程，无当前ESP32-S3直接运行适配。不把moc3视为可直接转换的轻量骨架，不依赖移植完整Cubism引擎作为前置条件。

## 6. 素材契约与宿主流程

参考与分层源图→桌面姿态/动作/表情/嘴型预览→导出贴图、父子关系、支点、关键帧、绘制顺序和触摸区域→边界/引用/容量/来源许可校验→仓库登记→独立设备切片验证。

新格式独立标识、版本与能力要求，禁止冒用PET4；定义尺寸、坐标、时间、循环、组合、摘要及资源限额。包内引用受约束，不加载任意脚本或外部路径。复用现有仓库与激活能力前先评审契约差异，不能假定现有package_schema=2已经支持分层包。

新增代码MIT；参考形象、改编图、上游代码及运行时分别核验来源许可，复制前登记。AI辅助拆层或补画仍需统一参考与人工确认，不自动解除原素材许可；大素材不进入Git。

## 7. 阶段与验收门槛

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 标准与样本 | 参考、标准底稿、完整静态拆层（含12层头发及末梢补画）、坐标契约 | 用户确认形象/比例/位置；静态合成不露缝 |
| P1 视觉动态原型 | 呼吸、眨眼、摆头、摸头及11处发束/末梢动态完整开放 | 宿主组合/中断正确，错相/滞后/回弹自然；暂不以性能删减效果 |
| P2 基础角色（部分实现） | 桌面已含待机、思考、工作、单次完成组合；短挥手控制亦有桌面候选，过渡观感待确认；开心扩展、生气及所需补画仍待实施 | 无关节穿帮、动态安全区通过；头饰稳定、末梢连续，中断过渡正确 |
| P3 双路线 | 分层与PET4协调、资源交接和恢复 | 无明显大小/位置跳变、黑屏或持续资源残留；失败不破坏旧角色 |
| P4 对话（已延后到真机阶段） | 保留五嘴型/无音频预览；恢复后做板端音频播放、音量嘴型及时间戳同步 | 用户明确恢复并另写专项Spec/Diff；真机核对播放时钟、声画同步、停顿/中断/欠载/换句与并发资源 |
| P5 性能优化、长期与离线 | 在完整效果上测帧率/延迟/内存，再优化缓存/重绘；恢复、切换、断网并发 | 记录优化前后观感与资源；坏包、失败恢复及离线本地交互有证据 |

后续性能阶段参考目标为稳定24FPS（每帧约41.67ms）、触摸首次可见反馈尽量低于100ms，不作为当前P0/P1削减效果的门槛，也不是实测能力。测量平均与长尾耗时、最大间隔、跳帧、延迟和内存，区分软件提交与面板刷新；设备指标不得从桌面预览推导。覆盖下载/保存/音频并发，实测后再定预算。若优化最终必须改变视觉效果，明确取舍后再由用户确认。
