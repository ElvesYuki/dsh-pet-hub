# P1设备协议与模拟闭环 Spec

日期：2026-10-29；状态：管理端设计草案，可实施模拟器，尚未完成固件评审/真机验收。

## 本轮交付及范围

交付hub-device/1消息契约、legacy v4迁移/回退方案及可追踪模拟验收清单。本轮只更改本仓库文档，不实现设备通信、不改固件、不导入素材、不启动/切换现有桥接、不安装插件、不提交推送。之后先执行离线模拟闭环，再独立授权实物接入。

事实依据：只读重查固件仓库tools/round-pet/bridge.py、catalog_state.py、apps/round-pet/main/app_main.cpp和reports/{firmware-lossless,catalog-lossless}.json。旧报告固件摘要为a117e9ef4d85ce5fcc2e4b6e38aeaa17ee026356188f578a7b7fb979106c4029；这是报告基线，不是本轮读取设备所得镜像。固件工作区可能有未提交修改，不以HEAD代替运行版本。

## 设计目标

1. 身份、能力、绑定、连接、控制所有权和播放进度分别建模，支持一块当前板，模拟时验证两设备隔离。
2. pet只提供state/counter；来源不可用与语义null分开，不把桌宠progress当实体回执。
3. 控制代数由设备仲裁、持久化；lease/session/boot隔离旧连接，不能仅依赖管理端单实例锁。
4. 下载校验不等于播放；只有当前命令首帧提交回执触发计时，同命令重试不得重播或重置计时。
5. v4必须显式legacy模式，不自动识别成新协议，不以IP/MAC伪造身份，不代理到pet本机端口。

## 职责

| 模块 | 职责 |
| --- | --- |
| core | 注册表、能力匹配、按设备目标/回执、模拟时钟、优先级和状态机；不依赖DSH/网络 |
| runtime | 单实例、凭证引用、认证transport适配、连接/重试、配置提交和IPC；不把秘密交给UI |
| source-pet | 已有公开只读接口及版本/能力差异，只提供有限语义 |
| shared UI/DSH入口 | 设备/来源/控制状态展示、用户意图；不直接持有连接/控制租约 |
| 固件（未来） | 身份/密钥、认证握手、能力、持久控制代数、素材校验、帧提交确认及本地输入 |

## 冻结与待定

冻结到模拟阶段：字段语义、状态机、不变量、错误码、尺寸/编码匹配、恢复和回退门槛，详见[消息协议](../../protocol/hub-device-v1.md)。

尚不冻结：LAN具体承载（HTTPS/持续连接/轮询）、TLS/设备证明具体实现、证书/密钥安全存储、BLE GATT UUID和配网密码交换。模拟器从可信测试认证上下文开始，不实现“自制认证”。上线前必须补充承载/认证子Spec、依赖锁定、资源预算和负面测试；模拟消息通过不能作为开放LAN监听/传Wi-Fi密码的依据。

## 后续实现顺序与门槛

- S1：纯core注册表/控制租约/按设备回执，可信认证fixture+虚拟时钟模拟两设备，过全部确定性案例。
- S2：显式simulation服务模式、只含合成设备的IPC设备摘要和UI；默认运行仍不接设备，模拟标识不能隐藏。
- S3：单独审查承载/认证、固件diff与NVS/Flash布局、旧版本恢复产物，用户授权后才接实物。
- S4：一块当前板验收后，再开展BLE配对及多实物设备。

退出条件：本轮文档字段/迁移边界一致，清单能直接导出测试；下一轮模拟过清单不是“已支持无线配对/真实多设备”。原P0 DevicePlayback仍为旧内存示例，不宣称实现本协议。
