# 本机任务六档状态 Spec 与 Diff

原有来源选择不改格式，DSH 本机、Codex 本机和已配置的 pet 兼容源都使用同一套标签。六档为思考、工作、整理、等待、完成、出错，另有空闲和来源不可用。管理页只展示已归一化状态。原有映射保持为思考 1、工作与整理 2、完成 3，其他由设备本地策略接续。

DSH 继续按单会话读取 `sessionController.state`，在同一游标按有界页读取公开 `sessionController.events`。仅取回合起止、工具调用与结果、等待和终态字段。处理排队中的实际审批及问题，多工具尚未返回时保持工作。完成与失败由回合结束原因确认，中断回空闲。自动 goal 续跑中的完成不作为整个目标成功。宿主不注册第二份会话监听。

Codex 的验收目标为日常桌面 App。已有传输连接明确配置的本机 App Server Unix socket，不要求安装独立 CLI。`thread/read` 的活动和等待标记结合 `thread/turns/list` 的最新一轮摘要投影，工具状态用于区分工作与整理，回合 `completed`、`failed`、`interrupted` 用于区分结束原因。请求最多一轮摘要，不展开全部历史。会话正文和工具结果不会进入管理页、配置或日志。新线程暂未写入回合或旧端点缺少细节时，只显示可确认的基本活动和等待。当前打开的 App 未发现公开控制 socket，隔离随包引擎只验证该协议。若需替代入口，另测 App Hooks 能明确提供的状态和权限，`Stop` 单独不能作为成功回执。

身份切换、来源错误、游标回退和连接重建都重建基线。独立来源仅接受已观察过活动状态的同一回合的终态，完成或出错显示 5 秒后回空闲。庆祝只认同一回合及当前设备连接上已观察到的活动边沿。现有 pet 兼容源保留原去重边界。

Diff 涉及 DSH 与 Codex 的只读适配、核心回合隔离、状态标签及隔离验证。验收覆盖六档、空闲、取消、并行工具、陈旧终态和跨来源切换，使用临时宿主、合成会话及本机 Unix 端点。真实 Codex App Server 对照另记装载范围。日常配置和圆屏留下一轮联调。
