# legacy bridge v4 迁移与回退

范围更新（2026-10-30）：本页旧v4/128步骤保留历史兼容。当前1.75C前瞻仍是旧HTTP v5，新的[单设备Spec](round-pet-single-device-spec.md)和[正式基线](../native360-baseline.md)优先；不得据本页恢复旧v4或旧整片冒充前瞻/a7回退。

> 历史128/v4迁移参考。当前正式目标已切175C原生360 production/v5；本计划不能直接用作该设备的迁移或恢复步骤，须补v5专门Spec/Diff。

2026-10-29；设计，**未切换任何运行链路**。旧桥接/旧固件继续作为用户当前基线。本轮只读来源是tools/round-pet/{bridge.py,catalog_state.py}和apps/round-pet/main/app_main.cpp，未复制其源码。

## 1. 当前事实与不兼容点

| 旧链路 | 当前事实 | 新协议要求 |
| --- | --- | --- |
| /v4/state | 三个文本整数action/revision/prefetch，服务端全局调度 | 按已认证device/binding/boot/session独立目标 |
| /v4/played/ID/REV | 只核对全局动作/修订，无身份，HTTP成功不等于本次回执被采用 | 全部控制上下文、report_seq和阶段校验 |
| 固件确认时刻 | native240路径先bind播放器并排队ack，之后才解码/提交帧；可每5秒重报 | playing必须首帧成功提交后报告；accepted/verified不能开始展示计时 |
| /status | bridge/dsh/全局playing摘要，无设备心跳；status内部调用get，可触发定时调度推进 | 认证的新seq心跳、来源/连接/控制/实际播放分别展示 |
| Bearer | 共享token、LAN明文HTTP、token通过USB写配置 | 独立设备绑定、撤销、认证和机密传输；旧token不作为新绑定凭证 |
| pet_config | 只接受裸http://数值IPv4:port，写pet_remote配置后重启；不接受路径前缀或HTTPS | 后续新固件单独配置namespace/承载；不能通过改URL偷偷升级协议 |
| 素材 | PET4原生240、四槽PSRAM，无Flash持久化 | 保持格式/摘要/许可及现有画质预算，不能把协议升级当素材格式升级 |

旧playing只称legacy_acknowledged，不标成新协议首帧回执。IP、现有token、相同动作ID都不能作为已完成新绑定的证明。不能复用同一全局v4 state给多个设备再声称独立调度。

## 2. 模式与权责

| 模式 | 行为 | 本轮状态 |
| --- | --- | --- |
| current external v4 | 用户已有固件/bridge继续运行，hub不代理/托管/修改 | 保持原样 |
| synthetic legacy fixture | 离线模拟v4解析、弱确认标签和单设备限制 | 下一轮实现，无真实endpoint |
| future explicit legacy adapter | 用户逐项授权后，最多一个legacy_slot，明确无认证身份/心跳/强回执 | 未实现，不自动启用 |
| hub-device/1 | 必须新固件、认证绑定及能力协商；独立控制与回执 | 仅设计 |

legacy_slot是管理端本地槽标识，不是device_id；UI用“旧协议设备（身份未验证）”。未来adapter只能选择一种调度权来源：旧bridge继续调度时hub仅观察；hub接管时旧bridge停止对该设备调度，不能双写。/status读取也可能推进旧调度，观察前应有明确频率/副作用说明，不能称为纯内存零副作用接口。

## 3. 分阶段迁移门槛

### M0：本轮设计

核对字段/确认时刻/配置约束，写Spec/Diff和模拟清单。本轮不读token文件、不读NVS、不请求正在运行的bridge、不改端口或服务。

### M1：离线模拟

完整过SIM-01至SIM-30的必选项，含双设备、旧服务复活、确认乱序、掉电提交失败、v4语义弱化。使用微型合成素材/虚假摘要，不导入鲸鱼娘大文件。失败只改模拟器/本仓库，无设备恢复操作。

### M2：认证/承载与固件变更评审（未授权执行）

- 先冻结transport/认证子Spec并验证库版本；明确NVS新增namespace/版本、epoch原子提交和断电恢复，不擦除clock_net/pet_remote。
- 对照当前实物与报告确认旧固件镜像、分区/启动参数和可重现构建，不能仅凭报告中的bin SHA认定已有可恢复产物。
- 确认旧bridge启动方式、素材manifest SHA与许可证、恢复所需旧凭据在安全存储中可用。只记录脱敏存在性，不把秘密复制到Git/报告。
- 定义新固件development绑定流程及一块板上的资源预算；USB只作开发途径，不把该实验宣称BLE已配网。拒绝把明文Bearer方案移植成新协议安全层。
- 列出具体构建/烧录命令、写入分区和恢复步骤供用户审查；未授权前不运行构建/烧录、串口配置或桥接停启。不要读整片Flash作为普通日志，那里可能含凭据。

### M3：一块板的显式切换窗口

未来仅在用户同意时执行：停止旧链路对该设备的控制（不结束DSH/pet，不占用其端口）→备妥恢复物→新固件/新协议独立endpoint→设备侧开发确认绑定→能力/单素材/首帧/重连验收。新endpoint不覆盖原v4地址，不共享token，不更改PET4画质。

新固件不得同时轮询v4并接收hub-device/1命令。若旧bridge还服务其他对象，不能笼统杀掉整个服务；先明确本设备停止旧控制的具体机制，无法隔离就暂停迁移。

### M4：通过后保留回退窗口

验收通过才逐步恢复自动来源；先验手动/本地触摸和资源，再验pet语义。实测记录冷下载、热切换、断线、重启、长期内存和首帧定义；不能要求新握手在现有内存预算下天然保持24 FPS。多实物另验。

## 4. 回退矩阵（未来实物操作前必须具体化）

| 失败点 | 动作 | 完成条件 |
| --- | --- | --- |
| 模拟或承载未通过 | 不进入实物阶段；保留现有链路 | 当前设备无需更改 |
| 切换前缺旧镜像/凭据/分区证据 | 停止迁移，不试烧 | 恢复物经摘要核对且用户可安全使用 |
| 新固件首次连接/资源失败 | 停新hub设备通道，确认无法继续发控制；按审核地址恢复旧固件及旧配置 | 旧v4重新提供匹配PET4，设备恢复legacy ack；pet设置未变 |
| 绑定/epoch新增存储有问题 | 设备侧明确重置新协议绑定，保留旧namespace；若涉及分区变更，使用独立审核恢复步骤 | 旧namespace可用，新凭据明确失效/撤销状态可见 |
| 离线且无法确认撤销 | UI标revocation_unconfirmed，不声称设备已解绑 | 物理确认/可信回执后再清理相关恢复信息 |

回退不需要erase-flash；若发现只能整片擦除才能恢复，应重新评审，不临时执行。恢复旧固件可能保留新协议epoch/凭据namespace：回滚前必须停用新控制，设备侧撤销或明确记录未确认，不能把旧固件不读该namespace当作已撤销凭据。

不承诺自动固件回滚：当前无OTA流程。所有上述实物动作待单独授权，并在固件仓库按其规则写变更计划。

## 5. 软件回退

下轮模拟代码通过显式simulation开关装配，关闭后回到当前devices=[]/deviceTransport=false。文档本轮只新增链接和事实，不动既有服务。未来若插件UI失败，只停用隔离profile中的hub入口，独立hub和外部v4需各自明确停启，不能顺带杀pet/DSH。
