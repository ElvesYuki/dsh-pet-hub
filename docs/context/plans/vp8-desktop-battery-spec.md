# VP8 Desktop USB 电池查询 Spec

终端契约为固件仓库 `docs/protocol/round-pet-vp8-battery-usb.md`。候选仅用于签名 Desktop 0.2.2-rc.3 的合并设置页，复用私有查询配置、Connection、IORegistry 身份前后核对和现有 USB 排他。独立读取 `BATTERY1`，保持 STATUS2、配对及维护语义。设备端无新网络入口。

## 采样和退出

- 仅设备页挂载时，且当前免码查询 owner 可用、目标无明确冲突时请求采样。首轮在状态读取后触发，之后每次完成约 5 秒后再请求。650ms 轮询继续读取宿主快照。宿主每个 owner 最多一项在途，5 秒内拒绝重复工作，USB 忙则跳过，避免排队。
- 现有受限 Connection 增一条 POST，其中只能用当前 owner 实例和短期请求标识请求/取消电池读取。页面退出取消 fetch、清理定时器并通知 owner 取消该请求。取消标识短期有界保留以应对到达顺序，宿主另有截止，等待实际 TTY 关闭才释放 USB。
- USB 每请求生成随机 8 小写十六进制 ID，只接受该 ID 的完整合规回包。旧固件无回包归为不支持或超时，忙碌、限流、不可用与节点消失分别反馈。

## 投影与验收

关系 true 在主卡显示，关系未知独立展示，明确冲突隐藏电池值。展示 0%、na、无电池、充电方向、充电阶段和 USB 供电，充电方向来自 flow。瞬时失败可在 15 秒内显示标记为旧值的最近成功采样，节点消失和 owner 变化立即清除。数据只存页面内存。

宿主验证报文边界、实体身份不符、共享 USB、取消/关闭、650ms 快照与 5 秒采样分离、归属和过时值。主包候选升至 0.0.3，登记包继续用 0.0.2，回退只替换主包。现场安装与真板验收由现场任务执行。

## 主包根入口修正

现场安装 0.0.3 后仍能读回设备版本，电池区缺失。rc.3 从包根导出加载宿主，0.0.3 的 `exports["."]` 与 `main` 指向两个宿主。0.0.4 将合并主包的两项都指向合并宿主。普通包沿用原入口。验收从实际 tarball 按包名导入，在临时运行目录装配 rc.3 设备页路由并读取宿主实时状态，确认 `batteryAvailable` 和电池路由。回退使用现场原主包 0.0.2。
