# P0 Spec（实现前，2026-10-29）

目标：建立独立设备管理仓库，验证本机 pet 的只读语义来源和 DSH 插件接入边界，提供可测试最小骨架。

架构：核心 → 纯数据与按设备播放状态；source-pet → 仅白名单语义；runtime → BLE、凭证、单实例抽象；ui → 可复用视图模型；dsh-plugin → Cordis 生命周期装配。系统辅助进程计划独立于宿主，页面不直接访问系统 BLE。

P0 只实现纯核心、受限只读适配器、展示模型及手工装配的插件生命周期骨架。无需安装依赖，不启动后台服务，不暴露 LAN 接口，不自动发现/连接设备。DSH client 打包和原生 BLE 延后。

验收：静态语法检查；本机 state GET 可达且仅输出语义；宿主测试验证不串设备确认、拒绝旧修订/旧会话、输入拒绝、网络请求限制、生命周期释放。所有真实运行集成均先形成方案及回退，另经用户授权。

排除：烧录、改桥接/DSH配置、安装启用插件、复制动画、提交推送；无线配对实现、OTA、1.75C、音频、IMU、独立应用发行。

## 上游参考补核（2026-10-29，实现前追加）

直接读取PC2005-cloud/dsh-pet的公开API/Cordis文档及源码，固定上游提交。按能力探测页面getState，存在时优先读取并过滤语义；缺少成员与尚无首拍分别标记，不在适配器内隐式启动第二个HTTP源。宿主/独立进程维持公开HTTP来源，不依赖页面常驻。
