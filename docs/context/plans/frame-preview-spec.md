# 离线帧预览与资源恢复 Spec（实现前）

2026-10-29，延续simulation/streaming。先完成宿主侧可观察的RGB帧预览、后台任务超时和显式恢复，不接设备、不写外部仓库/运行配置、不安装插件或提交推送。

## 范围与契约

- PET4 decoder在worker内提供单帧RGB565LE字节；原status仍只返回帧摘要。新增鉴权POST /v1/roles/frame，经同源插件白名单转发；只允许读取已激活设备的当前actual，绑定服务实例、激活revision、意图revision、动作/帧/像素摘要，禁止网页路径、任意版本/帧读取。
- 响应最多360×360×2字节，base64封装；只对此固定IPC路径放宽响应上限至384KiB，其余仍64KiB。worker转移独立帧ArrayBuffer，不传整个素材。每设备最多一个预览请求，不排队；返回前复核actor、会话、意图、actual及事件，变化则409丢弃。
- 共享React画布显式开启，当前像素转换为RGBA、按设备屏幕原尺寸居中并裁圆，虚拟帧变化后拉取；一个组件只保留一帧，关预览/卸载/版本变化取消请求并清画布。不增加实时来源监听或自动推进虚拟时间，不能称24FPS动画性能验收。SIM2明确无像素，不伪造宠物画面。
- 后台store验证默认120秒期限，单次prepare/frame/pixels/release RPC默认2秒；最多8个在途RPC，超额立即拒绝。超时使该worker失败并终止，清理stage/预留/pin、拒绝所有在途请求，晚到结果不改变失败状态。期限为宿主调度策略，不能保证阻塞磁盘/事件循环的硬实时上限。
- 失败关闭共用一个完成Promise；已确认指针和最后actual仍保留。新增显式retry恢复确认版本，重验缓存/许可/能力/首帧，不自动修复坏blob、不自动换包或重试；离线/健康/过期revision拒绝。重连、重激活或恢复后旧意图不能因revision重新归零而生效，服务内保持意图revision单调。
- 状态投影每角色/候选的worker存活、RPC在途/高水位、超时次数等有界指标；不存逐帧日志/像素历史。正常退出、失败、超时、取消和重复切包都回收worker与暂存。最多仍基础导入+两设备+一个候选4个worker，不承诺总RSS≤32MiB。

## 验证与回退

实施中压力探针发现旧simulation会话在第129个请求因缓存硬上限停止。先补充本Spec再修复：仅仓库合成会话的请求结果缓存改为最近128条FIFO（内部提供有界统计），窗口内仍精确重放/拒绝同ID不同参数；淘汰后的原请求带旧expected_revision，按原CAS拒绝，不能重复推进。窗口外不保证永久识别被重新使用且携带新revision的请求ID，客户端必须保持ID唯一。不得将此变更扩展为设备协议命令的无限期exactly-once保证；旧core IntentScheduler/DeviceModel的请求/触摸/命令上限仍另评审。

使用原创PET4两规格、多帧彩色fixture覆盖RGB565LE/帧摘要、360居中偏移53、不同帧、旧revision/实例拒绝、同设备背压及跨设备隔离、像素请求期间切换/断连的迟到结果、卸载取消。使用可控worker故障验证验证期/RPC超时、错误/退出、并发close一致与资源清理；重复激活/恢复和多次取帧验证有界请求/无stage泄漏。真实素材如复验只读已审核非商用来源，不将动画加入Git。

执行前方案：构建候选并运行宿主用例，再以独立临时runtime/loopback浏览器预览原创PET4，检查实际canvas像素与控制台；退出关浏览器/预览服务并删除本次目录。回退停止这些独立进程，仅撤回本轮代码；持久指针与坏缓存保留供诊断，已提交版本需显式再激活旧包。真实DSH/pet/桥接/设备没有本轮操作。
