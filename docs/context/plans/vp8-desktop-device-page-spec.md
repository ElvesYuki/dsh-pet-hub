# VP8 桌面宠物设备合并页 Spec

2026-11-17。现有 rc.3 同进程已读回真板，真实新板首绑仍由未来窗口验证。本轮交付独立可配套安装的主 Hub 合并页与原登记包后端版。当前 App、USB、签名器、私有配置与原 Hub 安装只由现场任务操作。

## 页面和授权

显式 rc.3 合并产物在 Desktop 由主 Hub 注册唯一 `dsh-pet-hub-settings`，名称「桌面宠物设备」。登记后端包保持 `dsh-pet-hub-boot-review` 与配置契约，不发布客户端槽。非 Desktop 和普通构建保留原 UI。Desktop 首屏只有 USB 设备卡，显示目标机型、从设备状态读到的固件及槽，分开呈现本地绑定和设备核对。未绑定主操作为「绑定设备」，已绑定主操作为「验证绑定」，待确认使用「核对绑定」。保留「查询设备」免码只读入口，旧固件、绑定后端不可用或缺少能力时仍可查询。合并页使用现有 Connection 路由和请求授权，GET 无 USB I/O。点击、服务重开、断线及错误不会自动重发写操作。

## USB 生命周期

两包通过同进程互斥持有到实际 TTY 关闭，保留 OS 独占层用于 CLI／外部进程。失败关闭保持隔离。UI 在两路任意操作期间禁用其他 USB 操作，后端仍防异步竞态。两套私有配置的 USB 身份只在宿主内比较；如果目标不同，区分只读查询属于另一个目标，避免把固件／槽位与本地绑定混在一起。原接口只在显式合并装配中附加最小布尔状态。

## 验收和回退

构建两种显式产物并复用原包名，原有普通／历史产物保留审核摘要。真实构建客户端测试验证配套包只有一个槽、主要状态与按钮、失败和轮询互斥。宿主覆盖并发、USB 释放、只读权限和身份冲突。交付配套 tarball 供现场任务安装，回退使用同一 App 恢复两份原包和既有配置，不迁移 Keychain 或登记数据。

### rc.3 已打开页面的升级修正

现场主 Hub 0.0.1 已显示合并页。登记包 0.0.1 完全移除客户端声明后，已有 renderer 仍保留旧设置槽。登记包 0.0.2 保持同一后端和配置，提供显式空客户端，使用原模块 ID `dsh-pet-hub-boot-review` 和原客户端名称 `pet-hub-boot-review-client`。空客户端无 React、无 slots 注入、无设置槽或请求。依靠同身份热替换释放旧客户端的注册。打包回归和现场均确认单独替换登记包后，原主 Hub 0.0.1 保留唯一入口。

### 查询结果与绑定归属

现场确认登记包 0.0.2 已替换为单入口，绑定可从设备核对。USB 查询成功后，主包 0.0.1 在目标关系未解析时仍显示「尚未查询」。主包 0.0.2 在 STATUS2 成功且固件版本与槽位均有效时，若 `sameUsbTarget` 为 null 或缺失，就在独立的「USB 查询结果」区域展示，标注「与绑定目标的关系待核对」。只有 true 才能把字段归到绑定卡；false 继续提示冲突并隐藏字段。查询结果不推进绑定核对状态。已部署登记包 0.0.2 保持原样。打包回归覆盖 true、false、null、缺字段及失败；现场仅热替换主包，必要时从同一 DSH 恢复主包 0.0.1。
