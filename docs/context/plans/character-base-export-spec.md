# 360标准底稿导出 Spec/Diff

2026-10-29。用户确认按“第一版透明源稿＋固定注册→360标准PNG→检查→拆层”的路径实施。第一版作为工作底稿，第二版仅备份；现有PET4与设备不替换。

## 输入与不变量

- 源图：本地neutral-review-v1/neutral-v1.png，1254×1254；实际SHA256冻结于导出记录，不重生成或覆盖。
- 注册：registration-v1/registered.svg及registration.json；单一等比系数、平移、360画布与固定原中心沿用已验证结果，不自动trim、fit、重新居中或非等比拉伸。
- SVG内嵌PNG必须与冻结源图相同；生成前复核SVG矩阵与JSON一致。输入变化拒绝，不盲目重算接受。

## 输出与实现

新增scripts/export-character-base.mjs作为离线导出协调工具：显式源图摘要、源目录、注册目录与新输出目录；复用已有安全文件读取与PNG CRC校验。工具只写本仓库.cache内新目录，拒绝已有目录/符号链接。

使用预装工具运行时的Sharp把已有SVG渲染为360 PNG。通过显式--renderer-module提供模块，项目package.json和设备/插件不增加依赖；渲染器不进入dist。将栅格化与美术生成分开，本轮不调用imagegen重新绘制。测试注入原创合成PNG渲染结果，不依赖外部Sharp安装。

导出neutral-360.png、manifest.json、静态原图/标准底稿对照页；校验PNG签名、CRC、360尺寸、RGBA、实际alpha和外框。抗锯齿后的像素边界与几何误差分开记录，不声称内部眼口已经逐像素对齐。记录源PNG/SVG/输出摘要、注册矩阵和渲染器版本。PNG仅为完整合成底稿，不是已拆层工程或PET4文件。

版本化制作路线记录，链接本地底稿位置，源/派生美术保持忽略不进Git。检查原待机、注册SVG和标准PNG同尺寸效果；边界、透明边缘、眼口与服饰细节分开验收。已有部件首稿待按该底稿修正再合成，不用各部件自动铺满画布。
