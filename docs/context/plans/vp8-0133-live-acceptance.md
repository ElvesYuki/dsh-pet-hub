# 0.1.33 Hub 真机联调 Spec 与 Diff

固件任务已读回 `0.1.33`／`ota_1`，`0.1.32` 留在 `ota_0`。Hub 线程独占本轮 Hub listener 和测试 USB。先用已封包的 rc.5 候选跑隔离联调，保留设备绑定、现有 LAN 配置和两份固件。

| 阶段 | 验收 |
| --- | --- |
| USB 首条与交接 | 插线后应用不打开设置页也收到同一 USB 的 Status v2，核对版本、槽和上报间隔。配网 INFO 和升级前 STATUS3 走正式前台路径，确认退订及描述符释放后才获得独占持有，读完后恢复订阅。 |
| 纯电池 | 同一认证 TCP 会话中实体拔 USB，取得至少两条新状态且 `usbPower=false`。插回原接口后确认 TCP 不掉线，USB 仅收附着首条，随后退订。 |
| 失联与恢复 | 对自有 TCP 会话暂停入站，记录距最后有效状态至 6 秒回 USB 和 9 秒关旧连接。新会话首条状态取得后观察至少三轮设备上报周期，确认 USB 不再周期读取。实际 AP 断网单列证据。 |
| OTA 范围 | 先执行真实升级前查询和串口交接。需要实际写入的用例由固件方案保证 `ota_0` 回退和原绑定可恢复，证据分别记录。 |
| 日常换装 | 验收满足后备份现用 UI 包和 profile。先离线预演同名换包以及目标 LAN 配置，再切换同一日常 profile。原窗口核对版本、来源、原绑定、页面外持续状态和回退入口。 |

Diff 优先为联调工具、证据和文档。若真机发现缺陷，先列明独立的代码范围与回归用例并重建候选；现用包保留。测试退出关闭 listener，排空任务、释放串口，通过同一已核对 USB DISARM。现场切换失败时关闭主动状态开关并恢复原插件包及配置，按固件交接恢复板端槽位。
