## 目标与边界

从原视频直接取更宽的400×400区域，保持源像素、人物大小和固定中心，增加两侧动作、道具及特效的可见范围。候选默认不加333或其他素材圆形遮罩，只在预览中按466物理圆屏裁切。380／400圆形遮罩仅供对照，不提前决定最终遮罩。

不覆盖原文件、旧360包、已确认指针或设备缓存；不自动扩大正式动作名单，不迁移分层角色的360坐标／11发束，不改pet状态来源、服务配置、固件或分区。固件仓库只读，不执行其脚本。真机适配与设备测试需另行授权。

## 固定几何候选

| 项目 | 候选规则 |
| --- | --- |
| 输入 | 核对每个原视频的实际尺寸、帧率、时长、alpha与来源摘要；示意来源为640×360 |
| 裁区 | 整数坐标x=124、y=-6，宽高400；源几何中心(324,194) |
| 空白 | 640×360输入在此裁区上方补6、下方补34像素背景；左右取源x=124至523 |
| 空间处理 | 不缩放、不逐动作平移；先解码为明确像素格式，避免YUV色度对齐悄悄舍入裁区 |
| 设备放置 | 466×466内居中，左上(33,33)，中心(233,233)，1:1显示 |
| 对比基线 | 直接360裁区(144,14,360,360)，对应设备偏移53；400比其左右各多20源像素，人物落在设备的位置不变 |
| 旧365方案 | (142,12,365,365)缩到360；其几何中心(324.5,194.5)与整数候选差0.5源像素，记录差异，不冒称完全相同 |
| 屏幕边界 | 仅保留方形裁区与466圆屏的交集；400方框四角超屏不可见，边中点33余量不代表四角有余量 |

原视频alpha须显式核对并按约定合成黑底，不根据RGB黑色推断透明。所谓原像素只表示空间处理不重新采样，颜色转换、调色板及RGB565仍有量化，不能宣称最终无损。

## 动作筛选规则

按用户第二轮意见，原46项保留；新增32项允许不严重的边缘与次要粒子／装饰损失。全帧几何与关键帧人工复核见[第二轮报告](../../reports/2026-10-30-native400-rescreen.md)：建议形成78项视觉候选，但不自动安装或扩大正式设备名单。保留原动作ID，初期语义映射沿用旧合同；新增／替换核心语义须单独确认。

1. 生成完整源画面、直接360、直接400的同帧对照，叠加物理屏幕；提供无额外遮罩、380圆、400圆三种对比。
2. 按完整动画的alpha轮廓记录：超方形裁区、超物理圆屏、超可选素材圆的像素数、最大伸出、发生帧与部位。区分人、重要道具、次要粒子，人工复核；量化阈值与alpha策略在工具Spec中版本化，不照搬旧值冒称视觉真值。
3. 裁黑底可以接受；手、头饰、主体、重要道具不能仅因文件或几何合法就判通过。次要粒子损失由用户看对照确认。记录“保留／裁切可接受／需修改／暂不采用”及理由，不只给总通过数。
4. 核对原帧率／帧数／时长和循环，不能为统一格式静默补帧、变速或截断。当前正式24fps／241帧约束保持；不满足的源动作标记待处理，另议时序方案。

旧333遮罩与旧轮廓筛选阈值是历史制作规则，不是硬件要求。旧半径109.5（240尺度）换算到360为164.25，而333圆半径166.5；不得把两者混成同一个准入值。400候选不继续依赖这个历史硬阈值。

## 性能假设与待测指标

黑色对压缩通常有利，对解码／缓冲不免费。所查固件播放实现有damage／局部失效路径，稳定黑边可能减少更新，但变化矩形可包含黑色，切换或回退可能整帧更新；本轮没有测量当前设备。

| 算术对比 | 360 | 400 | 含义 |
| --- | --- | --- | --- |
| 像素数 | 129600 | 160000 | 增加23.46%，不是总耗时增长承诺 |
| 单RGB565帧 | 259200B | 320000B | 多60800B，约59.38KiB，不受黑色压缩影响 |
| 三RGB＋1字节history | 907200B | 1120000B | 若维持同布局，多212800B，约207.81KiB；未含全部工作集 |
| 单帧base64 | 345600字符 | 426668字符 | 400仅base64已超过当前384KiB帧响应预算，尚未含JSON |

测量必须在相同动作、相同帧率和相同缓冲策略下对比：压缩大小／最大片段／Flash占用、顺序及跳转解码时间、CRC／颜色转换、内存峰值与最大连续块、damage面积／实际刷屏字节／耗时、首帧与切换延迟、漏帧／重复源帧／取消退出。覆盖静止黑边、小动作、宽道具、大范围移动及全帧回退，不只测待机。

先采宿主证据；ESP、显示总线、真实网络和并发TLS必须分开实测。24fps每帧约41.67ms是时序参考，不是以平均fps通过的准入标准；正式门槛须在设备测试方案中冻结，并满足既有更严格内部RAM／PSRAM／栈／最大块及认证余量，不能吃掉TLS预算。数据不足时维持未准入，不靠降帧／缩人物／删校验掩盖。

## 适配范围与回退

- core：PET4当前仅240/360、大小及tile20／帧数限制；新增profile须逐项审核，不直接放宽成任意尺寸。400可被20整除，不代表其他约束自然兼容。
- runtime：严格导入、单动作／库配额、worker内存／输出、角色切包保护与候选失败恢复；真实编码后重定限额，不按面积直接上调全部上限。
- IPC/UI/宿主代理：frame校验与序列化长度、base64、JSON、服务和代理响应上限一致，仍限定帧接口；400居中偏移33。小响应64KiB限制不随之放宽。
- 包与设备能力：独立尺寸／recipe版本、遮罩策略、来源／许可批准、新文件和包摘要及命名空间；不把旧批准或旧摘要套用到新字节。G0三摘要／能力合同和设备存储兼容另审。
- 固件只读评审：固定360头检查／常量、三RGB/history／解码、damage坐标与全帧回退、LVGL尺寸偏移、Flash最大对象／流式读取／read-ahead／取消恢复。具体当前路径实施前重新冻结核对，不运行固件导入器。
- 分层角色继续360，400候选先限原视频/PET4路线；不暗中迁移画布或混用两套坐标。

所有候选输出使用新目录／profile，旧360包、确认指针、动作映射和可恢复固件保留。宿主候选失败保旧角色，不自动降级或覆写；设备回退在授权测试前单独验证，不能只凭PC文件备份宣称可恢复。无需为本轮规划安装、启用、烧录或提交推送。
