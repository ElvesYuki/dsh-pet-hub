# Codex App 本地 Hooks Spec 与 Diff

## Spec

用当前桌面 App 的隔离 Local 项目验收。项目级 `.codex/hooks.json` 由显式准备命令写入临时项目，供 App 原生审阅。项目绑定一个绝对的私有 Unix socket。Hub 只在显式配置 `taskMotion.codexHookSocket`、打开动画联动并选择 Codex 会话时监听。沿用现有选择和保存、权限路由与轮询器。已有 `codexSocket` 仍供明确提供 App Server 的环境使用，两个端点互斥。保持 DSH、pet、圆屏及现有 profile 的配置边界。

转发器接受 App Hook 的标准输入，丢弃会话正文、路径、工具名称、参数、结果和错误文本。Unix 消息 v1 只包含 `sessionId`、`turnId`、内部事件、发送时间，以及工具开始和结束所需的 `callId`。App 不接收控制决定，Hub 缺席或超时由 Hook 直接结束。接收端只处理已选择的会话。连接、报文大小、同时在途及读写截止均有上限，监听目录仅同用户访问。转发和状态只驻留进程内存。

| App Hook | 管理页投影 |
| --- | --- |
| `UserPromptSubmit` | 新回合进入思考 |
| `PreToolUse` | 工具开始，进入工作 |
| `PostToolUse` | 只结算匹配的调用，最后一个返回后进入整理 |
| `PermissionRequest` | 显示等待审批，下一有效工具事件或回合结束清除。适用范围按 App 实测记录 |
| `Stop`、`Interrupt` | 回空闲，禁止同一回合的迟到事件恢复播放 |
| `PreModelRequest`、`PostModelRequest` | 仅在主会话、没有工具或审批在途时，失败或取消的模型尝试可提前清除活动。后续实际重试可回到思考 |

成功和失败需要明确的回合终态。`Stop` 和单次工具或模型请求结果不提供此证明，Hook 模式在证据不足时只回空闲。App Server 摘要模式继续支持完整终态。活动和模型重试的观察窗口最长 120 秒，帧必须在本机 2 秒内送达。相同事件不延长新鲜度。切换来源或会话时排空旧监听；新监听从新的提交开始，不重放旧消息。保存结构保持原版本。

## Diff、验收与回退

- runtime 增加有界 Hook 消息转发、接收与按回合状态投影，宿主增加可选端点并复用原状态接口。现有页面和 DSH 读法保持原契约。
- 准备命令只对明确指定的项目写新 Hook 文件，拒绝覆盖。测试验证输入脱敏、并行工具、审批等待、重复、旧回合／旧会话、无事件过期、失败关闭、日常兼容与卸载清理。真实 App 记录项目级 Hook 的信任、状态序列及取消证据，和隔离 App Server 或合成回环分别记录。
- 回退时在页面停用动画联动，停掉测试接收端，移除临时项目的 Hook 文件。测试使用独立目录和宿主，不安装到日常 DSH，不操作真实圆屏。

## 现有仓库的桌面验收

Codex App 已保存指向仓库的 `dsh-pet-hub` Local 项目。项目根目录允许同用户所有且其他用户不可写的常用权限，例如 `0755`。准备脚本保留 `.codex`、生成的 Hook 文件及接收端目录的私有权限要求。项目级配置以独占创建打开，已有 Hook 时停在原地。仓库忽略本机生成的 `/.codex/hooks.json`。验收时命令指向私有临时目录中的转发器副本，审阅后的命令不随工作区编辑变化。

在专用 Local 聊天用 App 原生界面审阅 Hook。用 `taskMotion.codexHookSocket` 接独立宿主，保持设备承载关闭。验证选中聊天的新回合、其它聊天不进入状态投影、接收端重开后只处理新回合，以及 App 重启后继续使用原聊天。记录实际 App 状态和宿主模拟各自的证据。回退时停止临时接收端，经核对后只移除本轮生成的 Hook 文件，保留其它项目配置和聊天。

用 rc.5 实际加载器复测时，宿主 fixtures 需按当前 Schema 核对默认关闭的 `deviceLan`，包括空的 `discoveryInterface`。此处只同步测试期望。
