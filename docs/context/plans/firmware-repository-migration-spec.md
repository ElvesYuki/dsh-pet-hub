# 圆屏固件并入 Hub Spec

2026-11-20。目标是在同一仓库维护 1.75C-EN 固件、Hub 及设备协议。源仓的交接提交是导入基线。真机运行版本、最近的编译候选与回退镜像分别登记。

## 范围

- 导入日常圆屏固件、板级依赖、必要构建配置、宿主测试和共用协议向量。用源提交、路径映射和许可证记录来源。原仓保留为迁移前快照。
- 产品入口放在 `firmware/devices/esp32s3-touch-amoled-175c/`，可共用的组件放在 `firmware/components/`，宿主工具及验收放在 `firmware/tools/` 和 `firmware/tests/`。文件按职责命名，板型用于所在目录。素材规格集中在 `media/profiles/400x400/`；原 360 回退见既有发布记录。Git 仅收录需要的规格、校验元数据和许可说明。
- 管理端与固件从 `docs/protocol/` 共享文档和向量。新报文用独立 `version` 或 `schemaVersion`，二进制定义固定位置、位宽及不支持版本的处理。现有命令字、状态版本、签名上下文、分区、NVS、绑定和动作身份保持与交接提交一致。
- ESP-IDF、芯片工具链、锁定的外部组件、素材输入和发布版本各自记录。构建和宿主验证使用明确的构建目录。原缓存、素材大文件、密钥、签名镜像、Flash 转储、本机配置及与日常圆屏无关的应用留在仓库之外。

## 验收与回退

1. 从固件线程交付的完整提交导入，只读取 Git 对象。核对所有必要源码和第三方许可。外部依赖仅从固定版本解析，素材输入仍走现有校验。
2. 在隔离目录核对同一份状态、USB 登记、网络、天气和播放向量；运行固件宿主测试、Hub check/test/build 和 ESP32-S3 日常构建。检查分区与版本输出，记录二进制差异及原因。
3. 检查干净检出的构建说明可执行，构建不触及设备、签名介质和日常 DSH。仓库内接口验收通过后切换日常开发入口。真机仍在统一窗口验收。
4. 若移植检查失败，回到源仓固定提交及原构建入口；固件与 Hub 已部署的回退机制沿用原验收记录。在迁移验证完成前保留两个可追溯入口。
