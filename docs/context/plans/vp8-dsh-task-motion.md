# DSH 工作状态联动 Spec 与 Diff

## 来源与动作

Hub 后端每秒串行读取一个显式配置的 loopback pet `GET /dsh-pet-7340/state`，沿用现有 HTTP 上限和取消约束。只取 `workStatus` 的 `counter`、档位和会话归属。已安装 pet 0.4.9 从真实 DSH turn／tool／approval 事件生成状态。其公开快照只暴露 pet 当前选中的一条会话，按任务优先级聚合，无法确认应用焦点，也没有 turn ID。隔离候选因此须显式指定一条验收会话。只有 pet 当前选中的会话等于此目标才可动作，其他会话、外部槽、初始状态、来源错误和倒序均不触发。Hub 不另监听 DSH 事件。

| pet 档位 | 角色 0 的动作 |
| --- | --- |
| `thinking` | 1 思考冒泡 |
| `working`、`result` | 2 忙碌点按，按同一档去重 |
| `success` | 3 雀跃庆祝，只接受已观察到的本会话活动之后的首个完成 |
| `null`、`waiting`、`error` | 由设备本地策略接续。等待保留当前任务归属，错误结束该任务。 |

按语义边沿发送一次，`counter` 单独增加不续期。只在同一活跃且状态新鲜的认证连接上发送，初始和断链期间不排队。跨连接或来源中断时重建基线，过期动作与一次性完成永不自动重播。每条申请 1500 ms 消费窗。已发到板端的待处理 Play 沿用固件短窗口及触摸、专注等优先级。VPC1 没有撤销已有请求的独立命令，也没有整段播放完成回执。Accepted 与 Presented 仍分开归属各自票据。

## Diff 与验收

1. 在既有 pet HTTP 读取器增加独立会话投影。保持普通读者的旧返回形状。核心只接已投影状态和连接标记，管理任务边沿与完成资格。
2. VPC1 owner 增加当前连接一次性 Play 模式。LAN 仅在 VPL1 mode 3 有新鲜 Status 后提供绑定到当前连接的发送句柄。旧调用者沿用原 TTL 重连行为。
3. rc.5 宿主增加默认关闭的 `vp8TaskMotion` 候选配置，跟随现有 LAN owner 生命周期，无新增路由、UI、USB 写入或心跳。只有既有主动状态与 LAN 接线启用才启用来源。设备端和日常 DSH 此阶段不调整。
4. 覆盖两个会话、聚合外部槽、同态和 `result` 去重、完成只一次、缺失及终态、旧／新连接、断线窗口与迟到回执，以及实际私有 HTTP 到认证 Node／固件 C++ TCP 连接。真实 DSH 状态跃迁与真机首帧分别验收。禁用开关即可退出轮询，关闭原 LAN owner 时一起清理。上一日常包可直接恢复。
