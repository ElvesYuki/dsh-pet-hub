## 3. 内存/性能门槛

[预算数据](../../protocol/transport-budget.json)区分源码量、旧报告和设计假设，运行`node scripts/check-transport-budget.mjs`仅校核算术。

2026-10-30 G0以P2/P3更新：显式PSRAM6916777B，含FAST read-ahead65536B，系统／瞬态前余1471831B；P3记录最低空闲1404660B、最大块1376256B、内部59035B及main栈2376B，见[正式基线](../native360-baseline.md)。内部scratch已随FAST代码变化，不沿用旧30848B或旧版本clip/catalog sizeof作当前分配证明。最大内部连续块／TLS峰值仍未知。

当前配置RX16384+TX4096=20480B仅为TLS记录缓冲，不含握手/X509/密钥/context。旧128约37KiB下载余量与RAM EVAL试验采样不适用于当前production；历史数据留在[旧预算](../../protocol/transport-budget-legacy128.json)。

**旧包络已降为历史输入**：140KiB由96KiB TLS＋4KiB控制＋8KiB栈＋32KiB余量构成，不能覆盖当前固件内部≥48KiB门槛。若沿用前三项假设仅算术即需156KiB，仍不是测量或已定探针参数；最大连续块、任务替换／回收、可信时间和秘密持久化须G2先定设计、后实测，未知不强行握手。本轮不改预算JSON／代码，后续不得拿旧脚本输出当当前前瞻准入。

## 4. 完整恢复前置清单

本轮末native360 production源文件与根sdkconfig发生并发变化，故进入任何设备操作前还须先重新冻结源码/配置/产物快照，不能复用本轮摘要作为最新运行确认。

进入任何设备操作前须具备：

1. 用户确认的profile/实物/当前镜像与目标入口，旧应用、bootloader、分区表及构建配置摘要，并说明哪些已验证可恢复、哪些只是备份。
2. 旧bridge与素材manifest的恢复方法/摘要，旧凭据在用户安全存储中可用；报告仅记录存在性，不保存值。
3. 需要写入的精确分区/地址/长度及“绝不写”的区域。128应用报告起点0x10000与175的0x200000不同，禁止套错；具体刷写命令须在后续固件Diff中审核，本轮不提供可直接执行的刷写命令。
4. 新绑定数据是否写NVS、是否新增partition/eFuse、是否会影响旧程序读取，必须明确。若出现不可逆key/eFuse变化，暂停并另行审批，不沿用可回退RAM探针授权。
5. 迁移前停旧链路对本设备控制、新transport失败后停其监听/撤销候选凭据，才恢复旧入口；不结束DSH/pet，不抢现有端口。

## 5. 回退步骤（未来执行前具体化）

- 离线原型失败：仅撤回本仓库原型/临时数据，现有实物无变更。
- RAM资源探针失败：停止本次探针服务，确认没有NVS/Flash绑定写入，再只恢复经审核的当前175C原生360应用范围；不改分区/bootloader/缓存根，不erase-flash。
- 正式新绑定失败：冻结hub设备队列、关闭新TLS，按设备侧操作撤销新binding_epoch；若没有可信撤销确认保留revocation_unconfirmed，不能抹掉恢复信息后标成功。
- 回到迁移前175C原生360入口：使用已经审查的对应profile镜像和旧endpoint/凭据；重新检查缓存/播放/任务来源，私密配置通过安全渠道提供，不打印到日志。
- 新namespace留在Flash且旧应用忽略它，不代表已撤销。若恢复流程要求整片擦除、复写出厂资源或切回用户拒绝的画质入口，停止并重新确认。

当前准入：宿主密码学／Node mTLS／会话及scoped已完成，不重复补原型；固件G1维护、G2 TLS资源／可信时间／正式秘密持久化与恢复仍待验，**不进入实物接入／刷写**。下一按[单设备Spec](round-pet-single-device-spec.md)先A1–A4离线；联合G0与C01–C12确认后再安排下一阶段，不自动启动LAN服务或操作设备。
