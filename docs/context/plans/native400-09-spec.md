# 400-09 Spec：来源审阅保存、可信重开与只读展示

日期：2026-11-03。状态：已按先行设计完成离线验证；结果见[报告](../../reports/2026-11-03-native400-09.md)。依赖400-08；本切片仅原创临时文件与离线宿主测试，不读真实素材/cache/固件，不启服务或设备通道。新代码MIT，旧尺寸与400-03字节合同保持。

## 不变量与范围

- 复用400-08 inspector及实际单fd/64KiB流式reader，增加严格历史map校验；自SHA只检查结构与身份关联，不构成来源完整性或设备证明。重开须由调用者重新提供独立candidate与mapping批准，账本不能自行授权。
- 显式私有目录、独立有界64KiB单记录journal，protocol native400-source-review-journal/1，canonical SHA、uint64 revision CAS、wx写锁、文件fsync→rename→目录fsync。拒绝坏档、未知字段、symlink/hardlink/非私有文件/残留锁；不得静默修复覆盖。目录由调用者创建，默认不装配。
- 只保存最新历史record：安全来源名（≤128字符，无路径）、400-08完整map；不保存源路径、批准原文、媒体或运行配置。重开仅历史，重新实际读取源文件/全cache与每个payload SHA并匹配完整map后才是本次复验。复验不写revision；新审阅须CAS提交后才能发布本次通过。
- 单任务、有界期限与取消代数；取消/关闭立即阻止发布，实际fd/hook退出才释放busy。失败保留旧记录为历史。rename前失败保旧档；rename后（含写锁释放）失败表示提交未知，当前owner冻结写入/复验直到显式重开，不盲重试。取消后已完成的持久提交可保为历史，不能称回滚。
- 一次实例内revision/digest高水位拒绝回滚/同revision换内容；不提供跨进程或整盘重放防护。没有文件持续监视，“本次通过”是一次完成检查。
- core新增白名单公开投影；共享React管理骨架增加可选只读slot。显示历史/复验中/本次通过/失败/取消/关闭/未知、整文件SHA及媒体未全验、device_evidence=false；无路径/批准原文/设备actual/saved/库存/写按钮。没有IPC或默认服务接线。

## 验证与验收

原创28MiB sparse文件经真实400-08 reader保存、重开、复验；覆盖结构伪造、自SHA重算、独立批准缺失/错配、u64、源变化、CAS竞争、坏档/权限/链接/锁、写入前后故障与未知结果、取消/关闭/迟到结果/实际退出；只读投影和共享slot宿主结构检查。旧400-08输出与03合同/golden不变。运行专项、独立临时CLI、npm run check及npm test。宿主UI结构测试不声称浏览器/DSH加载验收。

候选不被默认CLI/IPC装配；关闭owner等待实际任务退出，保留journal供人工核定；新目录可隔离归档，不自动清理未知提交或锁。回退到400-08只读审阅不改源文件、设备或其他服务。下一宿主接线须另写Spec/Diff和回退。固件G0/N_boot正式协议、Flash proof/writer、TLS/时间/凭据、资源/24fps、真实用途批准与设备窗口均保持待验；不读取外部新状态，不重复承载优化。
