# VP8 新板 BOOT 登记管理端 Spec

2026-11-17。对齐固件侧 `round-pet-dsh-usb-enrollment.md`。驻留 `0.1.4` 的 USB 有 STATUS2 等文本维护命令，无 BOOT 配对。旧 PBP1 的 BOOT 输入、15 秒物理窗口、一次性挑战与持久绑定是迁移依据。旧管理实现首绑后直接申请 PMA1 RAM 租用，本片不调用该流程。

管理端先验证候选明确宣告首绑能力且当前未绑定，再显式创建待处理记录。记录保存精确设备、控制者、绑定 ID、代数与公钥指纹。进程先提交待处理记录，随后才能启动本次确认。由设备验签、显示提示后，只接受新的 BOOT 短按与松开。先按住、长按、错误按键或未收到确认的结果由固件判定。管理端本地超时只停止等待，不能推导设备提交失败。

正常完成要求当前尝试、USB 对端、boot、精确绑定元组、设备持久读回和新鲜挑战核验全部一致。回执丢失、超时、掉线、取消或本进程退出后保留 pending；恢复仅开启新一轮对账，无自动重发首绑。设备给出已绑定且经过精确元组和新鲜挑战的证据，才能提升为 bound。只有隔离旧尝试后的可信未绑定读回才能移除 pending。冲突或存储故障保留原记录等待处理。宿主模型沿用 25 秒本地尝试上限，看到等待状态后最多等 15 秒，并受该尝试剩余期限限制。实际设备的物理期限由设备时钟判定。

本片实现独立于线协议的事务模型。持久化以可信 CAS 存储接口建模，宿主夹具模拟提交故障与进程重开。输入的已验证语义事件只可来自未来 USB 验证器，不能从 renderer 或裸串口状态生成。后续冻结 VP8 能力与字节向量时接入实际串口、密钥后端、私有索引和界面。现有 DSH／pet 配置、`query.json`、串口、固件及设备分区保持原样。
