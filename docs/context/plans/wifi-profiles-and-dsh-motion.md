# 多 Wi-Fi 与 DSH 动作补齐

2026-11-20。以同仓 1.75C-EN 固件和已审阅的角色 0 动作作为离线候选输入。验证通过后按既定窗口统一联调。

## Spec

- 管理页通过现有已绑定 USB 通道读取最多四组 Wi-Fi，显示设备在线模式、连接状态、已保存列表与当前联网项。支持新增、按同一 SSID 更新和按条移除。固件仍负责网络轮换和本地在线模式。时间与天气输入在固件中为全局设置，保存 Wi-Fi 会一同提交表单中的值。
- 固件复用现有 `DESKNET3` LIST、SET、REMOVE 和关联回执。连接页面请求通过独立 `version` 字段选择列表契约，省略时沿用单 Wi-Fi。LIST 超时可显示旧 INFO 的只读状态。旧 CLEAR 在新版固件会清空整个列表，降级结果无法授权写入。写入先列表复核，再发一条明确操作。新版写入无回执后须重新读取。
- 已绑定设备、同 USB 描述符、实例与 revision 校验、凭证清零及旧会话拒绝沿用原顺序。收到 `saved` 或 `removed` 表示设备保存确认。LIST 的线上模式和活动项用于显示。列表按设备字节标识匹配，支持现有非 UTF-8 SSID 条目。
- DSH 继续思考 1、工作 2、一次成功 3。每次进入等待播放 41，观察到同回合活动后的出错播放 42 一次，整理持续满一秒后才发 43。短整理沿用 2。断线、来源失败、计数回退、换回合和迟到采样撤掉未触发的整理，重连时以首次样本为基线。Codex 与既有 pet 兼容源保留原动作。设备本地优先与 `Accepted`、`Presented` 契约继续沿用；缺素材依设备回执，不重试或自动写入。

## 离线验证结果

- 设置页候选验证了 USB LIST、满四项的长回执、原始 SSID 身份、单条移除、对象存在性确认、容量拒绝、旧入口的只读降级、无写回执后不重发。回查只能确认 SSID 是否在列表及当前连接状态。同一 SSID 的密码更换需要设备回执或另行联机验证。
- Node／C++ 使用固件真实的 USB 命令解析器与认证 TCP。合成 DSH 状态经过播放装配到达 C++ 对端，核对等待 41、工作 2、持续整理 43 和失败 42 的请求与回执。C++ 首帧由宿主模型提供。
