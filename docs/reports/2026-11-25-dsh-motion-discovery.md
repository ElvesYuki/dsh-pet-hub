## 工作动作超期排查

从现场私有观测记录核对，工作动作的 `sent`、`accepted` 和 `expired` 关联同一连接及请求。已装 `0.0.12` 包为该动作传入 1,500 ms。Hub 从派发起算本地期限，圆屏从接收起算播放期限。观测脚本只在 `receive` 校验完整票据后记录终结回执，Hub 本地清理 `desired` 的分支没有这个记录点。因此 1,655 ms 是 Hub 收到设备 `Expired` 的时间，精确的板端过期时间与传输延迟未分别采集。

对照 `0.1.45` 构建快照，设备会在等待领取或已领取待首帧的两个阶段返回 `Expired`。领取前会等本地交互与播放调度让出，领取后仍需读取素材、解码、等面板末段 DMA 完成并提交匹配票据。现场记录只确认设备在期限内没有提交有效的首帧回执，无法确定卡在哪个阶段，也无法判断 DMA 是否在期限之后完成。

新增两条 Node／C++ 认证 TCP 回环，用相同的 1,500 ms 有效期分别延后领取和首帧。宿主本地超期只更新动作状态，设备 `Expired` 到达后才更新最后回执。两条路径均拒绝迟到首帧。随后动作 43／3 可继续在原会话播放，或在立即重连后由新命令播放，过期请求未重放。回环的首帧完成由夹具触发。未改生产代码、日常 DSH 或圆屏设置。

固件宿主网络测试 2 项、新增认证回环 2 项均通过。`npm run check` 与全量回归通过，2,142 项通过、7 项跳过。

下一次集中验收记录同一票据的设备接收、是否及何时领取、素材就绪、首帧 DMA 开始／完成以及超期阶段。若未领取，采集当次拦截领取的本地状态；若已领取，按各段实际耗时定位。继续用 Hub 单调时钟记录同一票据的回执，从两端各自的时间差判断，避免直接对比未同步的时钟。保持原有效期和触摸优先约束。

## 自动待机让出播放修复

源码确认一个会导致同类超期的条件。设备自己挑选的待机动画使用和前台动作相同的播放索引，轮询只允许普通待机响应待领取的 Play。自动待机剩余时间长于有效期时，设备可先回 `Accepted`，随后在尚未领取时回 `Expired`。现场那次记录缺少当前片段来源，仍需真机复测。[修复 Spec／Diff](../context/plans/vp8-dsh-task-motion-live.md#自动待机让出播放-specdiff)

候选沿用播放器已有的自动选片标记，由 OTA 播放入口传到输入轮询。带标记的自动待机在下一次输入检查时可让出给有效 Play，新片段沿用原缓存领取及首帧流程。手动片段、睡眠、触摸、专注和配对提示仍用原优先规则。有效期保持 1,500 ms，票据和首帧 DMA 回执的字节契约保持原样。

宿主回归验证正在自动待机时动作 2 可在片尾前领取并确认首帧，前台输入或触摸仍会挡住远程切换，过期和断开时旧票据作废。固件宿主、Node／C++ 网络测试、`npm run check` 和 `npm test` 通过。全量 2,142 项通过、7 项跳过。回环的首帧由宿主夹具触发。

ESP-IDF 6.0.2 的日常 ESP32-S3 配置交叉构建通过。相对正式版构建快照，板型目录中的运行源码差异仅为此次改动的四个文件。未签名候选 `0.1.46-i-battery-usb-pair-test` 大小为 1,376,256 字节，SHA-256 为 `6be28f3494969d1a091c54d4edd9eaa38569b517a80f696044c894cf4e40f605`。分区表与 `0.1.45` 逐字节一致。候选和构建记录保存在本机忽略目录，正式归档仍用于回退。

下一轮真机验收在自动待机日志 `IDLE_PICK` 后触发工作动作，核对本次请求收到 `Accepted`、旧自动片段提前让出、同票据在期限内收到 `Presented`。再核对按住触摸时能延后切换，过期后松手不会补播。现有日常 Hub 和圆屏正式版保持运行。
