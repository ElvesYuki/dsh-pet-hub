## 实际改动及依据

- 新增 `packages/core/native400-bridge-events.mjs`：默认 OFF，无 Node/DOM/DSH 依赖。可信调用方固定同 boot/mapping/四资产作用域，显式选择 transport 与 remote 目标；旧代/旧目标先于时间检查隔离，同 token 不能换 intent。切换目标清旧 stage/首帧为历史，不从事件自动创建目标。完整 source/mail/cycle 关联区分 SHA、FrameReady、Remote View 首帧报告和周期完成；不推导 whole-media、saved、物理扫描或实际 I/O 退出。
- 新增 `tests/native400-bridge-events.test.mjs`、`scripts/verify-native400-bridge-events.mjs` 与 `native/native400-bridge-events-check.cpp`。内部 JSON 行仅供宿主审阅，不是网络 JSON。可选显式只读 include 端侧头，默认测试无外部文件依赖。
- 更新 README、当前系统/待办/索引/400基线、决策与许可说明；TCP01/03加后续事实/差异提示。被替代的当前记录移至[主题归档](../context/history/tcp04-evolution.md)。TCP01/02/03源文件、七消息布局、素材、依赖和默认装配不改，精确 SHA 比较见证据。

端侧实际 `control_bridge.h` 和 `app_main.cpp` 已有默认关闭的 worker/完整 SHA/首帧 CRC/View 完成/EOF 桥，不能重复标成待开发。关键差异：WholeSha 早于 Source.bind，source/mail仍0；同 Remote 意图换 source/cycle 但只报告一次 SHA/FrameReady/Presented；Touch 无 Presented；ConnectionClosed 不是 Touch 完成；Completed/失效不是物理 I/O 销毁。TCP03非零验证source、固定source与完整Touch状态候选须共同修订，因此本片不把两层硬接起来。
