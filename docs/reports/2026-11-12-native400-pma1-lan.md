# PMA1 单动作 LAN 联调调用者

2026-11-12。新增默认关闭的显式调用者与人工 CLI，仅允许动作 1、一个指定 RFC1918 IPv4 与固定非零端口、一份已激活的同 boot PBP1 RAM 配对、一次 ARM 和首条 TCP 连接。原 loopback sender 保持原准入。[Spec](../context/plans/tcp-media-pma1-lan-spec.md) · [Diff](../context/plans/tcp-media-pma1-lan-diff.md)

- `createNative400LanMaintenance` 在监听前固定 `plan.begin` 和 `plan.beginSha`。BOOT 配对给出 boot，root 与 generation 由实测侧只读提供。监听就绪后通过同一物理端口的独占 ARM 会话发送 type 5。布局为固定 180 B body，PSK 的 HMAC 覆盖无 NUL 域 `PMA1/usb-lan-arm/v1` 和前 148 B。SSID 为 1–32 B 且无 NUL，口令为空或 8–63 B 可打印 ASCII，槽尾为零，已按固件 `media_lan_arm.h` 和 `station_bootstrap.h` 对齐。
- 等到同 boot/device/proposal/fingerprint 的 `Active/OK` 才把首条已接入 TCP 交给 PMA1。PMA1 校验配对、boot 和库存，使用原素材文件预验、精确 GRANT、单块背压和回执。只有发送 END 后收到匹配作业、SHA、新根和代数的认证 `Saved` 才报告成功。连接结束后回收文件、监听、socket 和 USB。断链后的 Unknown 保留，单连接入口没有第二次查询或重发。
- BOOT 配对会先关闭宿主串口句柄，再重开同一端口发送 ARM。整个联调保持物理 USB 连接，ARM 句柄持续持有到 TCP 和文件退出。终端执行同子网拨号检查，主机须选 STA 所在子网内的实际接口。终端另有自己的 STA、连接和提交期限。
- PBP1 `STATE` 没有命令序号或 ARM 摘要，`Active/OK` 只表示队列确认。调用者独占重开、先排空并只发一条 ARM；丢失回执直接退出，既不重发也不以 INFO 补造 ARM 已接受。跨端仍需实测串口重开及晚回执边界。固件实际保存和读回由固件任务独立确认。
- CLI 不从参数或环境接收 Wi-Fi 秘密。使用无回显、无历史的终端输入。ARM 构建后清零调用方凭据字节，事务退出后清零报文。密钥沿用配对 `KeyObject`，无持久化或原始报文输出。Node 字符串及驱动内部缓冲无清零保证。

## 人工入口

仅由固件任务在确认候选与实测窗口后运行。预先设置下列公开参数变量，`ROOT` 和 `GENERATION` 使用当前设备活动根与动作 1 对象代数，`APPROVAL_ID` 和 `LICENSE_REF` 对应当前素材和用途。`MATERIAL_DIR` 指向已批准的 compact78 目录，`MANIFEST` 和 `INDEX` 为相应固定元数据。`PBP1_PORT` 和 `DEVICE_ID` 是独立确认的直连端口和 32 位设备标识。

```sh
pbp1_helper_dir=$(mktemp -d)
cc -Wall -Wextra -Werror native/native400-pbp1-tty.c -o "$pbp1_helper_dir/pbp1-tty"
node scripts/native400-pma1-lan.mjs --run \
  --port "$PBP1_PORT" --helper "$pbp1_helper_dir/pbp1-tty" --device "$DEVICE_ID" \
  --address "$HUB_IPV4" --tcp-port "$HUB_PORT" \
  --directory "$MATERIAL_DIR" --manifest "$MANIFEST" --index "$INDEX" \
  --root "$ROOT" --generation "$GENERATION" --approval-id "$APPROVAL_ID" --license-ref "$LICENSE_REF"
```

看见设备提示后短按 BOOT。CLI 显示 BEGIN 摘要。核对后键入 `ARM`，再分别输入隐藏的 SSID 和口令。退出或 Ctrl-C 关闭联调并撤销本进程配对。重做联调由固件任务安排新的 boot 和只读库存。CLI 对实物只验证了 `--help`。

## 首轮真机截止与发送节拍对照

固件任务回报，动作 1 首轮通过 BOOT、STA、PMA1 和 USB 单次 ARM。管理端在 30 秒截止报 `Unknown/media_deadline`，确认 2,673,856 B（656 块），终端暂存 2,677,932 B（657 块），目标 3,568,101 B（876 块）。设备写入期内部内存低点 52,099 B，已退出。暂存区 ROM 核对与恢复由固件任务负责。30 秒除以 876 块约为 34.25 ms／块，预验、认证、设备准备和结束确认还会占用其中一部分。

终端拨号的 `SocketOps` 已设置 TCP_NODELAY，既有 PMA1 回环也明确设置。管理端实际 LAN 接入此前没有设置。专用入口现在在端点核验后、首个协议字节前调用 `setNoDelay(true)`。单块在途、认证、SHA、`Saved` 门禁及原 30 秒上限保持。

原 CLI 结果追加 `timing`，仅包含聚合数字。 `totalMs` 从启动调用到 USB/监听清理完成，包含等待连接。 `tcpMs` 从 sender 接管 socket 到确定结果或失败，包含握手、预验、准备、DATA 和结果等待，不含清理。 `dataWriteMs` 汇总 DATA 编码、认证及写完成回调。 `ack` 含有效样本 `count`、`meanMs`、`maxMs` 和 `unacknowledgedMs`。ACK 耗时从对应写回调完成到累计确认通过校验，未确认的最后一块单列。无样本的耗时以 null 表示，统计不包含身份、地址、密钥或 Wi-Fi 数据。

macOS 隔离裸 TCP 对照，设备替身保持 TCP_NODELAY，交替开关 hub 端。每轮 128 次单块往返，DATA 4,160 B，ACK 84 B，无额外设备处理延迟。关闭组三轮总计时分别为 11.478、7.774、5.410 ms，开启组三轮为 7.418、6.184、4.679 ms。单次最大为 0.601 ms。该样本未复现真机量级，且包含首轮预热差异，无法确认 TCP_NODELAY 是首轮超时的根因。

下轮实板维持同动作、素材版本、30 秒和单块在途，保存管理端 `timing` 与确认块数，并与固件 DATA 收齐、Flash 暂存写完成、ACK 发送的聚合时间对照。若 ACK 等待仍主导，先按这三个阶段区分传输和设备处理。若 TCP 总时长与 ACK 累计差值偏大，再核对握手、文件预验、READY 和最终读回。故障对照仍按原备份与回退流程。

`node --test tests/native400-pma1-lan.test.mjs` 四项通过，包括真实回环 socket 选项、慢 ACK 与末块无确认的 Unknown。 `npm run check` 和启用既有 C++／NOR 回环的 `npm test` 通过，全量 2019 项、零跳过。此次管理端只运行宿主回环，未启动真实 LAN、操作设备或提交。

## 设备分段计时与 USB 状态修正
