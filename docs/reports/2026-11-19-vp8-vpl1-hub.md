## 接线与行为

- 候选 USB ARM 经现有私有索引、控制者 Keychain keyRef、同一物理 USB descriptor 的全摘要 Fence 后才允许。确认写出 ARM 后的未知结果保持未知。板端签名公钥在本次隔离候选进程内固定。网络只能用该公钥证明身份。退出和撤销清除进程内 pin。原绑定索引和 Keychain 数据格式保持兼容。
- 受信宿主通过现有 connectTelemetry 把 usbIdentity、attach 和 signal 交给 createVp8Vpl1Adapter。宿主只向其传入明确归属的 socket，默认插件配置不启动监听。适配器确认原 USB 绑定范围、Keychain P-256 签名、设备签名、ECDH/HKDF、双向 MAC 和 Ready。单设备限制为一条活跃连接和一条待认证连接。
- Status v1 共用一个 3 秒 Ping 和 Play 的 VPC1 序号分配器。Status 按会话与请求序号映射到原设备状态 owner，Pong 只完成控制探测。6 秒失去状态首选，9 秒关闭失联连接。EOF 和本地撤销立即撤下网络状态。重连首条新状态停止 USB 轮询并取消在途请求。能力 0 保留仅控制模式及 USB 状态。
- 同 boot 会话号递增，新 boot 成功完成 Ready 才切换序号范围。旧连接和历史 boot 不能恢复状态。该代际记录与 pin 只在隔离进程存活，候选重启需要物理 USB 重新核对。

## 验证

- v1 候选的 `npm run check`、构建和 rc.5 单包构建通过。全量 2114 项通过，临时 Keychain 对拍独立执行并通过。本机回退包位于 `.cache/vp8-vpl1-candidate/dsh-pet-hub-0.0.8.tgz`。

- 只读消费固件共享向量 `docs/protocol/vectors/round-pet-vp8-vpl1.json`，SHA-256 `e16a6b7f7d005bd4f042aa38cfe76f40cbb5a025b9e5f61fc22631b8e5dec382`。核对全量和缺省 Status、方向密钥、确认 MAC、记录、VPC1 旧 Ping/Pong，覆盖拆包、粘包、坏长度、截断、错计数、MAC 不匹配及错误设备公钥。
- 在自有临时目录用固件现有 C++ LAN Session、VPC1、PSA 适配与只读的宿主 PSA 库重编 ASan／UBSan 回环对端。实际 Node/C++ TCP 跑通认证、共享请求序号、模拟播放首帧、仅控制模式、同 boot 重连、认证新 boot 和拒绝退休 boot。另用临时 macOS 文件 Keychain（与日常环境独立）让固件 C++ 核验实际 Hub 签名，测试后删除临时文件。
- 3／6／9 秒用可控单调时钟驱动真实状态 owner。C++ 回环持续返回 Pong 与 Status，测试在已验 MAC 的 Status 交付处模拟状态丢失。核对 USB 读取从第 6 秒可开始，第 9 秒 socket 被关，重连之后真实取消信号触发。还验证 EOF 与撤销立即撤下网络状态。USB 采样由夹具模拟。
- USB C++ Fence 夹具验证 Fence 丢失时未发 ARM，同一模拟 USB 连接收到成功 Fence 后才处理候选公钥回执。物理串口、真实首帧 DMA、内存、功耗和 LAN 最坏延迟尚无本轮证据。

## 首次实板联调与回退

1. 在独立宿主将 listener、USB owner 和适配器保持为同一个测试生命周期。开放隔离测试地址后进行显式 USB ARM。若设备先于 pin 建立拨入，先拒绝该连接，等待设备重拨。新连接只有完成 Ready 后才能替换旧连接。同一进程仅允许一次明确 ARM 尝试。
2. 验证拔 USB 后网络仍可读取并触发原动作。断网后接回同一 USB 设备，核对回退顺序，恢复网络后确认停掉自动 USB。同步测 ESP 内存、功耗和实际首帧。
3. 退出时关闭 listener 和适配器并等待释放，撤销 pin。若设备已被 ARM，用受控物理 USB 执行 VPCNET1 DISARM；ARM 返回未知时先确认并停用旧路由。现有 USB 查询、配网和天气设置可沿原路径继续。更新固件、安装 DSH 候选及生产环境的密钥轮换、持久 pin 与端点发现另行验收。
