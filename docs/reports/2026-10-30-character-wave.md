# 短挥手桌面候选实现与验证

2026-10-30。按[Spec/Diff](../context/plans/character-wave-spec.md)实施。复用已制作的单侧抬手与原放下手臂，没有新增生成图；未改设备、固件、pet或既有运行服务。旧母版与预览保留。

## 行为与视觉范围

- 一次挥手2.4秒：进入0.45秒、轻摆三次1.5秒、退出0.45秒；摆幅上限4度，周期0.5秒，外包络逐渐起落。
- start活跃期返回busy、不叠加/排队；cancel绑定代数，拒绝旧代数。打断从当前抬起量/摆角开始用0.3秒平滑退出，不瞬间回零。
- 挥手只暂时拥有右臂绘制；基础态、自然弹簧、触摸、11处发束、眨眼及无音频嘴型继续求值。进入/退出时逐渐衔接当前基础右臂角度，结束回到最新基础态；不保存并恢复旧基础意图。

首轮肩肘腕三点仿射导致过渡手掌拉长，已废弃。当前采用肩腕两点相似变换，保持单张手臂图内部的等比比例；共同肩点为(195,216)，放下腕点(217,251)、抬起腕点(229,200)。两张图注册到共同腕点后，以互补权重在离屏画布lighter累积，再正常合成人物。原根位置/整体缩放固定；手臂在进入退出时会局部等比变化，不是移动或缩小整个人物。

挥手臂位于侧发前方，无挥手时恢复原绘制顺序。已目视关键帧，完整抬手和小摆基本保持静态候选形状，未见明显身体透明缺口。但两张图的手形、袖形不同，进入/退出中段仍可看到短暂的淡化双轮廓；这是制作候选，尚不是独立肘腕骨骼或最终自然度验收。若该过渡观感不接受，下一步应补中间姿态/独立前臂手掌，而不是扩大仿射剪切。没有把几何扫描为0作为遮挡/自然度通过依据。

## 验证

- npm run check通过；最后一次npm test为214/214通过。本轮新增4项挥手测试，覆盖一次性时序、三周期、重复拒绝、取消连续/旧代数拒绝、确定性回放、非法输入、肩腕定位及无剪切。此前静态抬手阶段的双时钟3项失败在当前工作区已不复现；本轮未修改其实现，历史报告保留当时结果。
- 浏览器实际按钮：开始挥手、活跃期间再次触发返回busy、打断进入exit；打断期间改为思考，退出后wave inactive且base thinking。14段固定组合覆盖基础态/触摸/完成/说话/挥手/取消/最新基础态，共4046次采样，低覆盖候选和越安全圆采样均为0。
- 挥手会移动原手臂，因此覆盖掩膜改为原body图alpha≥240、内侵蚀4像素的6133像素；不与前一阶段全人物内区31423像素扫描直接对比。该掩膜只筛查固定身体内区，不覆盖整条肩袖/头发边界；安全圆中心(180,180)、半径166.5，像素阈值alpha≥16。
- 原绘制部件SHA、表情manifest SHA与四态候选一致；360原点/根缩放保持。自然头发和原46个PET4动作无变更。演示24Hz是离线采样，不是桌面实时帧率或设备性能测量。
