# 挥手过渡双轮廓优化

2026-10-30。按[Spec/Diff](../context/plans/character-wave-contour-spec.md)修订既有桌面短挥手。当前入口v4，替代[v3的两张袖臂淡化](2026-10-30-character-wave.md)；旧目录及历史证据保留。

## 改动与效果

根因是两张袖臂的袖口、掌形和弯肘外形不一致：肩腕对齐后，按透明度叠加仍会在轮廓不重合的位置显出虚影。现在先对已经注册的两张袖臂计算局部有符号距离场，插值得到一条中间覆盖轮廓，再在轮廓内部过渡颜色。颜色由各自最近密实像素延伸，避免透明区域的黑色RGB污染边缘。该距离场采用两轮双向最近向量传播，是局部轮廓近似，不是完整骨骼/网格或精确欧氏距离SDK。

实际修改为新增纯RGBA函数scripts/character-arm-morph.mjs及自然预览的袖臂合成；导出器仅在--wave路径内嵌新逻辑。中间图的局部裁边带3像素透明余量，根据变换后的实际alpha范围计算，不用固定裁框截手。amount=0/1纯函数直接复制输入端点；完全抬起时预览直接使用抬手原图。

已目视同一wave场景下进入/退出25%、50%、75%的3倍像素对照：原先袖口外侧和手掌后的半透明第二层轮廓明显减少，中段呈现单个小掌/袖口边缘。仍是两张姿态的形状/颜色插值，肘部收细、拳掌到张掌的自然度待用户确认，不称新增关节源稿或全姿态已验收。

人物360基准、原点、整体大小、肩腕锚点、2.4秒时序、三次摆动、4度幅度和0.3秒打断退出均保持。表情、嘴型、触摸、基础态与11处发束逻辑不改。原绘制部件、表情manifest及抬手图SHA与v3一致，没有新增生成图；原46动作不变。完整画布前后截图保留为视觉证据，不宣称Canvas不同合成路径下全身RGBA逐像素相同。

## 验证

- npm run check与npm test（217/217）通过，新增3项：端点RGBA精确保留及非法输入拒绝；非重合矩形袖臂的中间结果是一个实心带而非两条淡边；最近密实颜色填充不会引入透明黑边。原挥手时序/取消/代数测试保持通过。
- 浏览器14段、4046次采样，固定body图alpha≥240内侵蚀4像素的6133像素内区，低覆盖候选为0；全可见像素alpha≥16越中心(180,180)、半径166.5安全圆候选为0。该身体掩膜不等于整条肩袖/手掌形状正确，不能代替视觉检查。
- 浏览器真实按钮开始、进入途中打断及切换思考：退出后wave inactive、base thinking；旧控制/有界历史依然沿用原逻辑。
- 导出8秒、360×360、192源帧/192编码帧WebP，延时合计8000ms。包含完整挥手、触摸与基础态变化及第二次挥手打断。24Hz为离线采样，不是实时性能测量。
