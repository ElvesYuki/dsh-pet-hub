# VP8 新板 BOOT 管理端离线验证

2026-11-17。[Spec](../context/plans/vp8-boot-enrollment-spec.md) · [Diff](../context/plans/vp8-boot-enrollment-diff.md)。

固件交接确认驻留 `0.1.4` 仅提供现有 USB 文本维护接口。未来候选计划复用 1.75C-EN 的 BOOT 低有效 GPIO0、历史 PBP1 物理确认与绑定记录。历史管理端适配器在首绑后还申请 PMA1 RAM 租用。VP8 事务保留可信 USB、明确能力与持久读回的设计，暂不调用旧租用流程。

本次新增未装配的管理端事务。支持提交待确认意图、接收可信的等待按键状态、取消与超时后保留 pending、从另一轮 USB 会话重新对账。成功提交需要精确设备、控制者、绑定 ID、代数、公钥指纹和本次 boot 与尝试一致。收到按键事件、裸状态、旧尝试或换板证据时无法提交。待确认记录只会因新鲜已绑定证据提升，或因已隔离旧尝试的可信未绑定证据清除。

四组定向宿主测试使用虚拟时钟和内存 CAS 夹具，覆盖 15 秒期限边界、精确 u64 代数、外来设备和旧 boot、退出重开、取消、旧回执及提交前后故障。模型没有接入实际持久化、串口、密码学验证器、DSH 插件或设备。已登记设备的免输入查询保持当前部署。

`npm run check` 和最终全量 `npm test` 通过。全量 2,043 项，零失败、零跳过。

## 联合接入所需证据

| 决定或待确认 | 后续交付 |
| --- | --- |
| 设备侧明确支持 VP8 BOOT | 定义能力探测与可识别版本。串口只有一个读主，确认二进制帧与现有文本命令共存、错长或半包终止规则。 |
| 物理确认由设备判定 | 设备输出等待状态，旧按下、长按、未松开、过期和掉线均拒绝。管理端超期后用新会话对账。 |
| 成功绑定要求设备持久提交、完整元组及新挑战 | 对齐公钥指纹长度、当前 boot、提议与回执的关联，确认如何在不发布 PMA1 租用的情况下验证 VP8 台架绑定。 |
| 可信未绑定必须表示旧尝试已被隔离 | 明确设备如何证明旧窗口不能再提交，并提供回执丢失、重启、存储故障、已绑其他控制者的向量。 |
| 密钥和记录分别由双方持久化 | 管理端接私有 CAS 索引和密钥引用，保留待处理意图并验证保护权限。现有 `query.json` 不隐式转换。 |

下一片先冻结双方能力与字节向量，再接独占 USB 适配和实际私有存储。实际设置页和实体短按等待单独的候选验证窗口。
