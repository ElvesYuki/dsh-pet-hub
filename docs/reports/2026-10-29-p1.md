# P1 基础设施验证报告

日期：2026-10-29。先写[Spec](../context/plans/p1-spec.md)/[Diff](../context/plans/p1-diff.md)再实现。不使用子智能体，保留之前未提交修改；无提交推送、烧录、安装启用或现有pet/桥接配置修改。本轮未连接现有pet HTTP服务或实物。

## 实现

- runtime/service.mjs：同一用户私有canonical目录内Unix socket内核bind选主。第二启动者读取0600描述文件，以随机token/instance握手并附着；来源模式/端点指纹不匹配拒绝。目录权限/所有者、描述文件非软链校验，socket为0600。没有TCP设备服务或18764监听。
- IPC只提供status、配置读取/CAS写入、页面语义报告。配置原子rename，未知字段/版本拒绝、冲突409。只有服务写配置。描述token不进入UI、Git或日志。
- 来源装配：disabled默认；HTTP为受限公开GET串行轮询，断连显式unavailable并继续尝试，取消中止在途请求；page使用公开getState按能力探测，pending/unsupported与空闲分开，3.5秒租约限制多页转发。无DSH会话监听，无pet写接口。
- host/client结构参考dsh-pet固定提交8963384e33400d0c83965bd82f98bd8f81d22863。宿主仅连接共享服务并提供白名单代理，卸载注销路由/取消在途请求，不停止owner；页面使用ModuleLoader工厂和独立settings.section id。来源页面卸载清定时器/AbortController。
- 共享React组件展示服务连接、来源状态、空设备列表和未开放配对按钮。不伪造连接设备。原生BLE、设备传输、固件身份/心跳、素材分发未实现。
- 零新增依赖。build生成dist独立候选，包含host入口、无顶层ESM的client脚本、bundle patch和许可证；未安装，宿主schema/peer/client解析仍待隔离验证。不是已经验收的可发布插件。

## 验证结果

`npm run check`、`npm test`（含build）、`node --check dist/client.js`和`git diff --check`通过。14组测试共覆盖：

1. P0设备/启动/修订播放确认、字段过滤、URL限制、GET/重定向/超大响应、host生命周期与公开页面能力边界。
2. 临时真实UDS并发启动、附着客户端退出不影响服务、Bearer拒绝、权限拒绝、配置CAS竞争只有一方成功、正常停机/重启持久化。
3. 两个独立Node进程同时启动，唯一owner/相同instance；SIGTERM清理socket，SIGKILL遗留socket后新启动明确阻塞，不删除锁或覆盖凭证。
4. 页面租约竞争/过期接管/未知状态，HTTP模拟失败恢复和在途取消。
5. 模拟宿主+真实临时HTTP代理验证路由白名单、同源JSON头、字段过滤、卸载后服务可用。
6. dist客户端在VM中注册唯一设置槽，组件取消在途请求；纯渲染输出无虚构设备。

修复测试发现的问题：Node默认HTTP连接池可能在服务重启后复用旧UDS连接导致EPIPE；IPC客户端使用agent:false建立独立连接，每次重新读取实例描述，正常重启测试通过。

静态UI预览通过浏览器截图检查：中文、来源pending、设备空态、禁用配对按钮清晰，无当前宽度横向溢出。截图保存在忽略目录.cache/p1-ui.png，预览仅为共享组件的静态渲染，不是DSH内截图；唯一浏览器控制台错误为未提供favicon的404，不涉及界面资源。预览未接IPC/pet/设备，测试后停止。

## 边界与下一步

单实例只覆盖相同canonical目录、当前macOS隔离环境；Windows命名管道/其他平台未验。同用户进程可以读取本机IPC秘密，不将此描述为隔离同用户恶意代码。异常遗留采用人工离线恢复，没有自动回收；原子rename不等于断电fsync耐久。设备端fencing、Keychain和LAN传输尚未实现，因此当前单实例不能推导为已具备端到端设备独占控制。

真实DSH模块加载、config schema注入、slots/React依赖解析、停用和pet共存未验；本机旧pet仍无getState，不升级它。[具体集成与回退步骤](../context/plans/p1-integration.md)已准备，下一入口是隔离宿主契约核对与审查配置diff，经授权后才安装试验候选。P1整体验收仍需真实设备管理协议及实物链路，本轮仅完成请求的基础设施与界面骨架。
