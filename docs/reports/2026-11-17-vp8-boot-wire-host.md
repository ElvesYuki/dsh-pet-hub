# VP8 BOOT USB 离线对拍

2026-11-17。[Spec](../context/plans/vp8-boot-wire-spec.md) · [Diff](../context/plans/vp8-boot-wire-diff.md) · [载体与回执提案](../protocol/vp8-boot-usb-proposal.md)。

当前 VP8 固件只接现有文本 USB 命令。旧 PBP1 源码已经定义状态探测、挑战、首绑签名提议与独立等待应答。对拍编译引用固件的 `BasicUpdateLines<384>`、旧 PBP1 帧解析和回执生成源码。VP8 候选分发、能力 bit 2 和 Base64 封装由本仓库的独立宿主夹具提供，含义仍待固件确认。

用 Node 与 C++ 比对 5 个完整应答的封装字节，含旧能力、候选能力、首绑等待、持久 Bound 状态和挑战。C++ 端用实际 VP8 文本行解析器验证 13 组字节流，覆盖逐字节输入、粘连、截断、坏 CRC、错方向、额外字节、非规范 Base64、控制字符、超长行和正常 STATUS2。Node 确认旧能力不能放行挑战，已绑定状态不能创建新提议，旧 boot／reference 不能接受为本次等待应答。对拍使用公开合成数据，临时二进制退出后清理。

`npm run check`、16 项定向测试及全量 `npm test` 通过。全量 2,045 项，零失败、零跳过。对拍通过 `ROUND_PET_BOOT_PEER_ROOT` 指定只读固件仓库，宿主编译步骤使用本地 C++ 和 OpenSSL。

候选联合门禁仍待固件确定具体能力和线上载体，以及无 PMA1 租用副作用的最终绑定证明与可信未绑定的终止条件。当前 132 只确认等待实体按键，129 只报告持久状态。两者缺少完成一次 VP8 首绑所需的新鲜验证。管理端私有存储和设置页仍等待联合门禁。现有免输入部署继续运行。

本轮没有修改固件仓库或运行其脚本；没有打开真实 USB、烧录或更新插件。联合验证可以按提案和 C++ 夹具先定输入，随后用固件自身的 VP8 分发器及回执向量替换候选分发。
