# VP8 本地动作控制离线契约

状态为离线验证。帧仅在调用方完成会话身份验证后交给状态机。真实 DSH 对接需要确定认证和会话编号协商，旧 PET4 PTC1 继续使用原版本。

## 帧格式

每帧固定 24 B，TCP 可分段或合并，整数为小端。

| 偏移 | 字段 |
|---|---|
| 0–3 | ASCII `VPC1` |
| 4 | 版本 `1` |
| 5 | 消息类型 |
| 6–7 | 保留，固定 0 |
| 8–11 | 会话编号，非零。同一设备运行期间新会话严格递增 |
| 12–15 | 会话内的请求序号，非零，回执照抄 |
| 16–17 | 角色 ID，0–65534 |
| 18–19 | 动作 ID，0–65534 |
| 20–23 | 类型对应的参数 |

| 类型 | 方向 | 参数 |
|---|---|---|
| 1 Play | Hub → 设备 | 命令在设备收到后有效的毫秒数，1–30000 |
| 2 Ping | Hub → 设备 | 角色、动作和参数均为 0 |
| 128 Accepted | 设备 → Hub | 0，已接收待执行 |
| 129 Presented | 设备 → Hub | 实际匹配的首帧显示序号，非零 |
| 130 Missing | 设备 → Hub | 0，待播放的素材当前不可用 |
| 131 Superseded | 设备 → Hub | 0，被更新的播放请求覆盖 |
| 132 Expired | 设备 → Hub | 0，已过设备接收时的播放有效期 |
| 133 Pong | 设备 → Hub | 角色、动作和参数均为 0 |
| 134 Duplicate | 设备 → Hub | 0，最近一个请求的完全相同重发 |
| 135 Cancelled | 设备 → Hub | 0，已取走的请求在首帧前由本地交互中止 |

## 执行语义

- 动作请求只有一个待执行位置。新请求覆盖待执行或尚未呈现首帧的旧请求。本地交互繁忙期间延后领取，超时后丢弃。播放器在启动时用设备本地目录判断素材可用性。
- 已领取的请求包含会话、请求序号、角色和动作。显示适配器凭该完整票据关联首帧 DMA 完成，在设备运行期间保持显示序号递增。重连、覆盖、超时或取消后的旧回调作废。
- 用新序号 Ping 保持会话。15 秒无有效的新请求即失效。完全相同的最近请求只回 Duplicate，一次也不重复播放，并且不续期。同序号不同字段、倒序、跨会话、方向或格式错时关闭会话。
- 每连接只持有一小段输入帧及固定深度回执队列。发送拥塞导致 8 条待发队列已满时关闭会话，清除待播、首帧关联和旧回执。断开后本地播放继续，重连由 Hub 下发当时仍有效的动作。

本地 TCP 验证使用 Python 独立编码，与实际 C++ 状态机交换上述帧。会话入口和首帧完成由测试夹具模拟，尚未接入圆屏、已配对身份或 DSH 运行服务。

## 固件首帧联调入口

开发候选开启 `VP8_VPC1_USB_PROBE` 时，可用物理直连 USB 驱动同一控制核心及真实 VP8 播放器。先发 `VPC1TEST OPEN <session>`，再发 `VPC1TEST FRAME <48 小写十六进制字符>`，结束用 `VPC1TEST CLOSE`，均为 LF 终止。外层命令应答 `@VP8_VPC1_TEST OPENED|CLOSED|BUSY|INVALID`，正常 VPC1 回执为 `@VP8_VPC1 frame=<48 小写十六进制字符>`。显式开启的夹具以直连 USB 串口作为入口，完成真实首帧前适用内层 15 秒心跳租约。

播放收到 Accepted 后，在本地触摸、菜单、专注或缓存提交让出时再领取。缺素材回 Missing。对应画布提交并收到 DMA 完成后才确认 Presented。失联、过期或覆盖时废弃旧票据。真实 LAN 连接和认证入口属于后续无线接入，DSH 日常页面不驱动此夹具。
