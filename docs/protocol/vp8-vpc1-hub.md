# VP8 VPC1 Hub 离线契约与无线认证提案

固件契约以固件仓库 `docs/protocol/round-pet-vp8-control-offline.md` 及 `tools/round-pet/vp8-probe/main/vp8_control.cpp` 为准。本切片使用相同的 24 B 定长帧、版本、字段、方向与状态值。计划中的联网方式由板子主动连接管理端。日常入口为「桌面宠物设备」，USB 继续负责配对、查询和维护，素材安装、OTA 及设备直接获取时间和天气继续走既有路径。

## Hub 实现边界

| 主题 | 固件契约与 Hub 处理 |
| --- | --- |
| 编帧 | 小端。保留位、角色／动作 ID、序号和类型专属值严格检查。TCP 按固定 24 B 切分，保留至多一个未完成帧，半帧 EOF 关闭。旧 PET4 PTC1 继续独立使用。 |
| 身份与编号 | 固件调用 `begin_verified`，Hub 的 `attach` 同样接受上层已确认的非零递增会话编号。loopback 由夹具明确提供，编号与魔数均不构成认证。会话内序号递增，耗尽关闭。 |
| 心跳 | 固件自上次新请求起 15 秒失效。Hub 夹具每 5 秒发 Ping，仅匹配的 Pong 确认心跳，5 秒无回关闭。Duplicate 和任意播放回执不确认 Ping。周期与无线超时是宿主实验参数。 |
| 目标与期限 | 只保留最新目标和本地单调绝对截止。新会话重发时，在新的请求票据里携带剩余毫秒。Missing、Expired、Cancelled 不自动重发。仍由上层持续持有、未过期的目标可在新会话重发，即使上一会话已经展示过。一次性触摸等事件应由未来来源接线单独管理。 |
| 回执 | `sent` 仅记录本地提交 socket，`accepted` 表示设备接收。只用匹配当前会话、序号、角色、动作和最新有效目标的 `Presented` 确认首帧，显示序号须在同一设备启动周期递增。Superseded、Duplicate 作为显式回执，Duplicate 保留原阶段。终止连接清除该连接的首帧确认，旧回调不能结束或更新新连接。 |
| 回执序序与背压 | 请求序号严格递增。回执按票据匹配，先返回较新 Ping 的 Pong 再返回旧 Play 的 Presented 合法。已终结的票据被忽略，未知未来序号、活动票据字段冲突、显示序号回退关闭连接。Hub 待回执上限 16，socket 达写入高水位即关闭。固件待发环仍为 8。 |

VPC1 的 TTL 从设备收包起算。Hub 只在本地截止内承认新首帧，网络排队可能让设备晚于 Hub 截止才开始或呈现。真实链路要核对端到端延迟与最小剩余 TTL。如果需要双方同时满足硬截止，应另定时钟映射和绝对期限字段。

## 无线认证和会话号提案

USB 首绑会保留 `device/controller/binding/epoch/keySha256`。板端保存控制者 P-256 公钥，Mac 私有索引保留相同身份元组及 `keyRef`。Keychain 私钥通过 `signTranscript` 签名，保持不可导出。已有 USB 类型 10／133 的 fence 能核对持久绑定及完整公钥摘要。它在受控直连 USB 上提供状态核对，尚缺可供无线 Hub 验证的板端签名身份。

1. 板端增加独立的设备签名身份。通过已验证的直连 USB 手续，将其公钥指纹钉到 Hub 中相同的绑定元组。设备继续用 USB 首绑保存的控制者公钥校验 Hub 的 Keychain 签名。设备密钥存储、更新、撤销和所有权转移由双方定稿。
2. 延续局域网明文 TCP，建议在 VPC1 外增加独立握手和报文认证层。两端以各自钉住的 P-256 身份签署同一规范握手摘要，覆盖独立 VPC1 域标签、双方角色和新鲜随机数、完整绑定元组、设备启动标识以及双方临时 ECDH 公钥。使用 HKDF 派生不同方向的会话 MAC 密钥，并做对应角色的密钥确认。双方须明确 Keychain 签名接口的输入上限和编码，避免把已计算的摘要当原文重复散列。
3. 控制者认证通过后，由设备分配本次启动内严格递增的非零 uint32 会话号。双方用握手派生密钥确认会话号和启动标识，达到上限时禁止回绕复用。24 B VPC1 保留为内层，外层 MAC 覆盖连接上下文、方向、独立的报文计数器及完整内层帧。计数器与请求序号分开，允许一个请求有多条回执。协议提供身份认证和完整性，动作数据在局域网内仍为明文。完成认证和编号确认后才能替换旧连接，凭据变更、解绑或回滚时撤销旧会话及待播记录。Hub 以设备身份和启动标识划分会话号与显示序号的检查范围，经验证的新启动才开新范围。

待双方确认设备身份与密钥持久化、标准密码实现和随机源、握手与 MAC 字节向量、既有 USB 用户授权、重连与会话接管、掉电撤销，以及触摸优先时的首帧票据。还需在真机评估认证与 VP8 并行时的内存和功耗。当前 LAN 装配待认证契约确认。

## 设置页状态探针交接

管理端宿主已实现按 3 秒探测、6 秒降级和 9 秒关闭的状态 owner。当前接口接受可信适配器传入的内部 schema 1 对象，包含设备版本、启动槽和可选电池、触摸及 IMU。收到当前连接探针对应的有效状态才更新页面和停掉自动 USB 读取。该对象与 VPC1 v1 字节格式独立。

联合接线时，需要在同一认证 TCP 会话定义带版本和序号关联的状态回执，以及缺字段、设备启动和撤销语义。当前 VPC1 Ping/Pong 的保留字段继续为零。正式接线需让控制与状态共用一套心跳调度，并核对 15 秒设备控制租约、拥塞时的闭合规则及 ESP 资源。普通 Pong 可以保活，页面仅认可匹配的状态回执。USB Wi-Fi 写入沿用 DESKNET2，天气和时钟的 TCP 写入另定契约。[管理端宿主证据](../reports/2026-11-19-vp8-desktop-status.md)

## VPL1 联合离线候选

本页前文保留裸 VPC1 控制和早期认证提案供追溯。实际封包、域标签、握手与 Status v1 以固件仓库 `docs/protocol/round-pet-vp8-lan-status.md` 及同目录共享 VPL1 向量为准。Hub 适配器沿用既有 USB 绑定和 Keychain，固定同一会话内经 Fence 归属核对的设备签名公钥。VPL1 在认证和完整性保护下传输明文，Ready 是控制和状态接管门槛。状态 v1 由原状态 owner 调度一个 3 秒 Ping，能力 0 继续裸控制的心跳节奏并以 USB 供状态。[实测与剩余门禁](../reports/2026-11-19-vp8-vpl1-hub.md)

## Status v2 迁移

最新候选按固件仓库 `docs/protocol/round-pet-vp8-status-v2.md` 和 shared vectors 协商 Status 2。USB STATUS3 与 TCP 认证状态共用公共载荷解码和维护标志。能力不匹配时只协商控制。Status v1 保留独立候选和回环证据。VPL1 认证、VPC1 动作及所有期限语义沿用。[Status v2 管理端候选](../reports/2026-11-19-vp8-status-v2-hub.md)
