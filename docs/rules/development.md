# 开发规范

适用于本仓库新增和修改的代码。沿用Node ESM、现有代码风格与零第三方依赖基线；不因规范整理引入框架、类型迁移或依赖。AGENTS.md中的操作授权、固件只读、pet边界及许可规则继续适用。

## 修改与架构边界

- 先确认问题根因、已有入口和真实调用场景。避免重复实现；新增兼容分支须说明适用版本或能力与退出条件，无引用的新增代码不保留。
- core保持DSH、DOM和运行环境无关；source-pet负责来源适配，runtime负责系统资源和持久化，ui负责共享展示和交互，apps负责宿主装配。通过明确公开入口协作，不为目录形式强加抽象层。
- UI通过既有客户端和宿主白名单代理调用；不自行访问文件系统、设备、凭据或拼接另一套鉴权/重试流程。
- 跨层调整、协议/持久化变更、控制权和资源回收等复杂改动，先写Spec/Diff，说明不变量、失败路径、验证和回退。局部修复说明影响即可，不机械增加文档。

## 契约与命名

- 目录、文件、模块、内部接口和界面按职责命名。采用 `device-status-sources`、`usb-status-subscription`、`desktop-host` 这类语义名称。协议代号、代际数字、固件版本和宿主发布版本集中写入协议、兼容矩阵和发布文档，构建所需的版本继续登记在包清单或构建配置。
- 新协议可在报文中用独立的 `version` 或 `schemaVersion` 字段声明版本。每种报文只定义一个权威版本位置；二进制协议可以把它放在固定帧头。协议文档写明位置、类型或位宽、支持范围、缺省规则和不支持版本时的处理。解码方先核对版本，再读取对应载荷。
- 已发布的命令字面量、帧头、版本值和签名上下文属于设备接口，由编解码器与共享向量集中验证。改变字段布局或含义时同步更新协议文档、向量和两端实现，源码重命名不改变收发字节。
- 对公开接口补充必要的JSDoc：输入、输出、错误、异步与关闭语义。沿用现有命名；desired、actual、pending、revision、epoch、session等术语保持明确区别。
- 跨进程、磁盘、外部来源输入在信任边界校验schema、类型、范围、长度及身份；明确版本、缺省值、未知字段和旧版本策略。内部已验证对象不层层重复校验。
- 协议uint64沿用十进制字符串/BigInt，不转换为可能丢精度的Number。需要稳定列表或摘要时显式确定排序规则，不统一按ID排序。
- IPC、持久化与UI转换集中处理；不把某一层全部内部对象直接暴露为公共契约。

## 错误、异步与资源

- 仅在能够恢复、补充上下文、清理资源或转换边界响应的位置捕获错误；不得吞错、假成功或用兜底分支掩盖状态不一致。包装错误时保留cause。
- 对外返回稳定错误语义；内部错误与对外响应分离，不泄露凭据、原始状态或不必要的本机路径。
- worker、socket、定时器、监听与在途任务都有明确所有者、容量、期限和关闭路径。关闭可重复调用，失败与取消释放资源，任务结束后才释放相关保护。
- 异步结果提交前核对实例、会话、revision或相应代数；旧结果不能覆盖新状态。明确失败保留的actual、确认指针及候选状态。
- 副作用结果未知时不盲目重试。重试必须由契约保证幂等；并发冲突不可通过自动覆盖消除。

## 持久化与一致性

- 由原子操作与CAS等机制保证唯一性和并发一致性，不以“先查再写”代替原子约束。
- 明确磁盘提交与内存状态更新顺序；写失败不推进确认状态，坏档保留并显式失败，不静默重建覆盖。
- 原子rename不自动等于断电持久化，多文件写入不自动等于事务。协议迁移说明版本识别、旧数据保留和回退边界。

## 测试与检查

- 修改后运行npm run check和npm test。优先覆盖行为不变量与真实失败边界：失败保留旧状态、旧请求拒绝、写失败、取消与关闭后的资源回收；不写只复述实现的测试。
- 使用临时目录/socket、合成数据与可控时钟；不从业务配置推断测试目标，不复用真实凭据或真实状态响应。fixture不得绕过被测授权路径。
- 清理自己创建的worker、子进程和临时文件。虚拟时间、宿主与真机验证分别记录；资源采样不外推为硬预算或多日稳定保证。
- 仅在新失败或未解决风险需要时扩大测试。代码、契约、证据和当前上下文同步更新。
- 当前check仅执行.mjs语法检查，test会构建候选。架构依赖检查、契约静态检查尚未实现；以后针对导入关系和打包产物补充，避免全文关键词误报。不得把本规范写成已有自动门禁。
